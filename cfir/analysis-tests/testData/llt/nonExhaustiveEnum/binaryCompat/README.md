# 非穷尽枚举的库版本语义检查

本目录沿用历史名称 `binaryCompat`。CFIR 诊断测试验证源码和类型语义；这些用例不执行旧客户端二进制与新版库的链接、替换或运行，不能据此证明二进制兼容。

每份用例使用测试框架已有的 `MODULE` 声明四个独立模块：

- `oldLibrary` 和 `newLibrary` 分别定义包 `a` 的两个版本。
- `oldClient(oldLibrary)` 和 `newClient(newLibrary)` 使用相同客户端源码，各自只依赖一个版本。

覆盖普通枚举新增项、泛型枚举新增带参构造器，以及通过结构体形成的递归关联类型。两个版本都保留枚举末尾的 `...`，客户端用 `case _` 覆盖新增项。

模块声明是编译输入的一部分。不能把旧、新版本的同名类型作为同一模块的文件编译；那会产生真实的重声明错误，与枚举穷尽性无关。运行器不根据 `.old.cj`、`.new.cj` 文件名推断或隐藏声明。

非穷尽枚举本身的负例位于上级目录的 `bad` 中。真正的二进制兼容测试还需要编译旧客户端、单独构建新版库、替换库并执行客户端，应由后端集成测试承担。
