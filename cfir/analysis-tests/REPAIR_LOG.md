## typealias36 - unresolved import qualifier cascade

- problem type: unresolved import qualifier cascade / import failure suppresses usage-site unresolved reference.
- root cause: failed non-star import binding with the same effective name was not represented as an imported package qualifier, so `pkga` in `pkga.AA` entered ordinary unresolved value lookup and produced an extra usage-site unresolved reference after the import checker had already reported the failed import.
- official Cangjie evidence: `cjc` reports only `package_search_error` on `import pkga`; `external/cangjie_compiler/src/Modules/ImportManager.cpp` owns the import failure, and ordinary unresolved-reference handling in `external/cangjie_compiler/src/Sema/TypeCheckReference.cpp` does not add a second usage-site diagnostic for this case.
- Kotlin counterpart files consulted: FIR error-node diagnostic collection suppresses receiver cascade diagnostics through `FirErrorNodeDiagnosticCollectorComponent`; package qualifier structure follows the `FirResolvedQualifier` role instead of treating the qualifier as an ordinary value lookup.
- CFIR owner files changed: `common/src/org/cangnova/cangjie/source/CjSourceElement.kt`, `cfir/resolve/src/org/cangnova/cangjie/cfir/resolve/body/CfirImportedPackageQualifier.kt`, `cfir/resolve/src/org/cangnova/cangjie/cfir/resolve/body/CfirCallResolver.kt`, `cfir/checkers/src/org/cangnova/cangjie/cfir/analysis/collectors/components/ErrorNodeDiagnosticCollectorComponent.kt`.
- repair principle: model an unresolved imported package qualifier as an already-reported error receiver at the shared import-qualifier/call-resolver boundary, so downstream member access and error collection see the real owner diagnostic instead of re-resolving the qualifier as a value.
