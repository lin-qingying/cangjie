# CFIR LLT Repair Log

## typealias36 - unresolved import qualifier cascade

- problem type: unresolved import qualifier cascade / import failure suppresses usage-site unresolved reference.
- root cause: failed non-star import binding with the same effective name was not represented as an imported package qualifier, so `pkga` in `pkga.AA` entered ordinary unresolved value lookup and produced an extra usage-site unresolved reference after the import checker had already reported the failed import.
- official Cangjie evidence: `cjc` reports only `package_search_error` on `import pkga`; `external/cangjie_compiler/src/Modules/ImportManager.cpp` owns the import failure, and ordinary unresolved-reference handling in `external/cangjie_compiler/src/Sema/TypeCheckReference.cpp` does not add a second usage-site diagnostic for this case.
- Kotlin counterpart files consulted: FIR error-node diagnostic collection suppresses receiver cascade diagnostics through `FirErrorNodeDiagnosticCollectorComponent`; package qualifier structure follows the `FirResolvedQualifier` role instead of treating the qualifier as an ordinary value lookup.
- CFIR owner files changed: `common/src/org/cangnova/cangjie/source/CjSourceElement.kt`, `cfir/resolve/src/org/cangnova/cangjie/cfir/resolve/body/CfirImportedPackageQualifier.kt`, `cfir/resolve/src/org/cangnova/cangjie/cfir/resolve/body/CfirCallResolver.kt`, `cfir/checkers/src/org/cangnova/cangjie/cfir/analysis/collectors/components/ErrorNodeDiagnosticCollectorComponent.kt`.
- repair principle: model an unresolved imported package qualifier as an already-reported error receiver at the shared import-qualifier/call-resolver boundary, so downstream member access and error collection see the real owner diagnostic instead of re-resolving the qualifier as a value.
- fixtures covered: `CfirAnalysisLLTTest.llt._typealias.TypealiasGenerated.testTypealias36`, `CfirAnalysisLLTPsiTest.llt._typealias.TypealiasGenerated.testTypealias36`.
- verification command: `.\gradlew.bat :cfir:analysis-tests:test --tests 'org.cangnova.cangjie.cfir.analysis.tests.CfirAnalysisLLTTest.llt._typealias.TypealiasGenerated.testTypealias36' --tests 'org.cangnova.cangjie.cfir.analysis.tests.CfirAnalysisLLTPsiTest.llt._typealias.TypealiasGenerated.testTypealias36' --no-daemon --max-workers=1 --console=plain`

- root cause: CFIR mapped `ConstraintMismatch` on the right operand of an operator-origin call through the ordinary argument mismatch path, because the semantic call abstraction did not expose call origin to the diagnostics layer.

## typealias_partial_infer_01/typealias_partial_infer_03 - partial static qualifier inference

- problem type: partial generic typealias/subclass static qualifier calls must use the qualifier as a static base expression for owner inference, not as an ordinary runtime dispatch receiver.
- root cause: CFIR correctly carried `C<T>` and `I2<K>` through qualifier scope, owner use-site substitution, and fresh variable creation, but `CfirCheckDispatchReceiver` still checked the class/typealias qualifier expression against the callable dispatch receiver type as a normal value receiver. That early receiver applicability check made the candidate contradictory before argument constraints could infer the owner parameter from `C.test(1, 2)` or `I2.f3(1, Int32(1))`, producing cascading `ARGUMENT_TYPE_MISMATCH` and `INVALID_BINARY_OPERATOR`.
- official Cangjie evidence: `cjc` accepts both `typealias_partial_infer_01.cj` and `typealias_partial_infer_03.cj` with only unused-variable warnings; `external/cangjie_compiler/src/Sema/TypeCheckCall.cpp` `CheckAndGetMappingForTypeDecl` documents `I2<K> <: I1<Int64, K>` and `I2.f3(1, Int32(1))`, deriving `F -> Int64`, `H -> Int32`, then `K -> H`; `external/cangjie_compiler/src/Sema/TypeCheckUtil.cpp` `IsEnumCtorWithoutTypeArgs` documents partial typealias access continuing into type inference; `external/cangjie_compiler/src/Sema/TypeCheckExpr.cpp` `HandleAlias` and `TypeCheckerImpl.h` `GenerateTypeMappingForTypeAliasUse`/`SubstituteTypeArguments` preserve alias-generated missing type arguments for further instantiation.
- Kotlin counterpart files consulted: `external/kotlin/compiler/fir/resolve/src/org/jetbrains/kotlin/fir/resolve/calls/QualifierReceiver.kt`, `external/kotlin/compiler/fir/resolve/src/org/jetbrains/kotlin/fir/resolve/calls/tower/FirTowerResolveTask.kt`, `external/kotlin/compiler/fir/resolve/src/org/jetbrains/kotlin/fir/resolve/calls/tower/TowerLevels.kt`, `external/kotlin/compiler/fir/resolve/src/org/jetbrains/kotlin/fir/resolve/calls/stages/CreateFreshTypeVariableSubstitutorStage.kt`, `external/kotlin/compiler/fir/resolve/src/org/jetbrains/kotlin/fir/resolve/calls/stages/CheckArguments.kt`.
