## 分析：当前库反序列化能否解析 char 形式数据头

**调查结论（针对 .cjo 反序列化链路）**

- `.cjo` 数据头 = FlatBuffers 结构：offset 0–3 为 uint32 根偏移，offset 4–7 为四字符标识 `CJOF`，
  其后是 `PackageFormat.Package` 表（cjoVersion / fullPkgName / imports / allDecls …）。
  schema 与官方 `external/cangjie_compiler/schema/ModuleFormat.fbs`（namespace PackageFormat）逐行一致。
- 三个反序列化入口全部**只消费根偏移，从不校验 4 字符标识**：
  - `cfir/cfir-serialization/src/.../cjo/CjoManager.kt:49`（loadPackageHeader，无 try/catch）
  - `cfir/cfir-serialization/src/.../cjo/CjoSearchPath.kt:120`（readPackageNameFromHeader，runCatching）
  - `analysis/decompiled/decompiler-to-file-stubs/src/.../file/CjoBinaryFileReader.kt:26`（readPackageFqName，runCatching）
- `CjoConstants.FILE_IDENTIFIER = "CJOF"` 是**死代码**；`Package.PackageBufferHasIdentifier`（= `__has_identifier`)
  只在 2 个测试里出现（CjoPackageWriterTest、CjoSdkDeserializationIntegrationTest）。
- 生成的 `getRootAsPackage` 只做 `bb.getInt(bb.position())`，不触碰 byte 4–7。
- 官方 C++ 侧 `ASTLoader::ASTLoaderImpl::VerifyForData` 会调 `PackageFormat::VerifyPackageBuffer`（ASTLoader.cpp:214），
  Kotlin 侧无等价 verifier。
- 版本：本地 `CjoConstants.VERSION_MAJOR/MINOR/PATCH = 1/0/5`，官方
  `external/cangjie_compiler/include/cangjie/Modules/CjoManager.h:20-22` 为 `0/1/0`，两边不一致。
- `CjoBinaryFileReader.isSupportedVersion` 在 `cjoVersion == null` 时直接返回 true，
  即老产物（只有 `version:string` 字符串头、无结构体版本头）被无条件当兼容。
- 实测头部字节：`c.cjo` / `default.cjo` / SDK fixture `cjo-sdk/windows_x86_64_cjnative/std.cjo`
  均为 `2c00 0000 434a 4f46` / `2800 0000 434a 4f46`，即合法 CJOF FlatBuffers。
