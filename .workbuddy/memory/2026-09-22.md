1. `:cfir:analysis-tests` 的 PSI/非 PSI 分歧**常源于诊断判定读 PSI 形状**。凡看到同一 fixture
   在 LLT 与 PSI 给出不同诊断名，先查判定里有没有 `source?.psi` / `PsiTreeUtil` / `textRange`
   这类只有 PSI 路径才非空的输入——light-tree source 是 offsets-only。

   对位锚在实参、不被抑制的 `sema_mismatched_types`。
3. `Candidate.symbol` 静态类型是 **`CfirBasedSymbol<*>`**，不是 `CfirCallableSymbol<*>`；
   在 stage 里要 `as? CfirCallableSymbol<*> ?: return`。
4. 需要「无候选但要构造以候选为结构化上下文的 cone 诊断」时的两条路：
   ①`components.resolutionStageRunner.createErrorCandidate(callInfo, context, 占位诊断)` 后直接
   `CfirErrorReferenceWithCandidate(source, callInfo.name, candidate, diagnostic)`；
