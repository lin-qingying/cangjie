## 调研：主仓 / intellij-ide 的宏辅助与展示能力（只读分析，无改动）

结论分层：

- 主仓（cangjie）提供宏底座，无任何 IDE UI：
  - `macro/macro-common`（MacroExecutor 接口、MacroDataModels、protocol/MacroMsgCodec、MacroSourcePositionUtils）
  - `macro/macro-process`（ProcessMacroExecutor + Pipe/Windows 传输、LspMacroServerMacroExecutor）
  - `macro/macro-stub`（StubMacroExecutor 桩）
  - 协议 schema：`flatbuffers-gen/flatbuffers/MacroMsgFormat.fbs`
  - `psi`：`.cj.macrocall` 文件类型（CjMacroCallFile / CangJieMacroCallFileType / CangJieMacroCallLanguage 方言 / CangJieMacroCallParserDefinition）+ CjMacroDeclaration/CjMacroExpression/CjMacroInput
  - `analysis`：`CaMacroExpansionMapping`（位置→展开面三态：RELIABLE/UNRELIABLE/NONE）+ `CaMacroExpansionMappingProvider` + `CaCfirMacroExpansionMappingProvider`
- intellij-ide `:modules:ide:macro`（39 文件）已有展示层代码：
  - `ui/ShowMacroExpansionAction`（Ctrl+Alt+M；EditorPopupMenu + ToolsMenu；光标在宏上→单展开，否则整文件多展开）
  - `ui/MacroExpansionPanel` / `MacroExpansionListPanel`（JBPopup + 只读语法高亮编辑器）
  - `ui/CjMacroExpansionLineMarkerProvider`（gutter 图标）
  - `service/`、`compiler/`（cjc-frontend --dump-macro）、`server/`（LspMacroServer 内存展开）、`pipeline/`、`cache/`、`psi/`（MacroPsiExpansionService 内存 PSI 替换）、`configurable/`
  - 注册于 `modules/ide/macro/src/main/resources/META-INF/cangjie-macro.xml`（2 扩展点 + 7 registryKey + 设置页 + 通知组 + 2 projectListener）

实测缺口（关键）：

1. `:modules:ide:macro` 未被装配：`product/idea-plugin/build.gradle.kts` 依赖列表无该模块；全仓仅 `settings.gradle.kts:176` 引用 → 不进插件产物。而 `modules/ide/base/.../cangjie-actions.xml:42` 已注册 `CangJie.ShowMacroExpansion`（类在 macro 模块）→ 描述符指向未打包类。
2. `CjMacroExpansionLineMarkerProvider` import `org.cangnova.cangjie.stubindex.CangJieMacroDeclarationShortNameIndex`，主仓无该包/类（无 `stubindex` 目录），`psi/build/libs/psi-1.1.1.jar` 中亦无 → 该文件编译不过。deveco 已据此剔除（见 deveco/docs/refactor-progress.md:369）。
3. 无宏专用 ToolWindow：`cangjie-toolwindow.xml` 仅 cangjie-project 生效；宏展示形态是弹窗，不是窗口。
4. 宏 PSI 展开未接语义分析：macro 模块外无任何引用 `MacroPsiExpansionService`/`MacroPsiReplacer`；registry `cangjie.macro.expansion.analysis.enabled` 注释明确"仅展示/调试，不得注入语义分析"。
5. `CaMacroExpansionMapping` 在主仓已提供，但 intellij-ide 全仓无消费点 → 宏展开前后位置互跳未接。

旁证：deveco 侧已移植整套宏模块（同一份代码），显式剔除行标，且未注册 ShowMacroExpansion action（其 XML 中无匹配）。

## 调研：宏的 IDE 辅助功能需求清单（依据来源，跨用例可复用）

权威依据（都在本仓 external/ 只读镜像内）：

- `external/cangjie_docs/docs/dev-guide/source_zh_cn/Macro/compiling_error_reporting_and_debugging.md`
  - 宏定义与调用**不允许同包**，必须先 `cjc --compile-macro` 编宏包，调用方用 `--import-path` 指宏产物
  - `--parallel-macro-expansion`（并行展开；宏函数用全局变量时有风险）
  - `diagReport`：宏内可发 error/warning，位置 = 传入 tokens 的 span（示例定位到 `call.cj:9:22`）
  - `--debug-macro`：生成 `<src>.cj.macrocall` 临时文件，块锚点 `/* ===== Emitted by MacroCall @M in file.cj:3:1 ===== */`，行前缀 `/* line.col */`
  - debug 模式限制：重排行列号（换行敏感场景不适用）、不支持宏定义内嵌套宏调用、不支持带括号宏
- `external/vscode_cangjie`：官方 VS Code 插件有 `cangjie.build.debugMacro`（Build With DebugMacro）命令与 `debugMacro` 启动配置（调试展开后代码）；`.cj.macrocall` 注册为文件类型；`docs/source_zh_cn/debug_service.md:51`
- `external/cangjie_deveco_plugins`：官方 IDE 插件对宏**只**注册了 `.macrocall` fileType + parserDefinition（`lsp-client/src/main/resources/META-INF/cangjie-lsp.xml:29,32`），无展开 action / 无行标 / 无 ToolWindow
- 业界：rust-analyzer `Expand macro recursively` 打开**只读虚拟文档**（TextDocumentContentProvider，第二列）；另有 `Rebuild proc macros`；completion 计算时内部展开宏，proc-macro 失败会导致补全丢失（降级策略是难点）

intellij-ide 现有实现与官方路线一致：`cjc-frontend --debug-macro`（展开，产物 `<file>.macrocall`）+ `cjc -p <pkg> --compile-macro -o <dir>`（编宏包），`MacroCallFileParser` 已解析 Emit 锚点与行前缀，`MacroSourceInfo` 已带 originalTextRange/expansionDepth/parent。缺的是体验闭环（装配、双向跳转、诊断接入、debugMacro、补全/跳定义）。

## 宏 IDE 辅助功能需求规格（与实现状态解耦的清单，8 组）

用户明确要求"不管是否已实现，只说应该实现哪些"。分组：① 编写调用（补全/跳定义/Quick Doc/参数与上下文约束校验/一键修复）② 展开查看（单点+整文件、递归与单层、悬浮/只读虚拟文档/diff 三形态、元信息、陈旧检测、导出）③ 映射与导航（展开块↔调用点双向、展开内符号导航、嵌套宏贡献着色）④ 诊断（diagReport 落调用点、错误映射回调用点、失败分类+quick fix、debug 模式限制提示、聚合去重）⑤ 宏作者侧（签名与分包约束校验、宏函数调试、展开快照 golden 与改宏前后 diff）⑥ 调试（--debug-macro 一键构建、debugMacro 运行配置、单步位置跟随）⑦ 工程与性能（宏包编译调度与缓存失效、请求去重/超时/取消/进度、引擎回退、全局开关、.macrocall 可见性与落盘、执行日志）⑧ 语义集成（展开参与补全/解析/结构视图且标注来源、失败降级不污染语义）。
最小闭环 = 能看（展开查看）+ 能跳（双向映射）+ 能诊断（失败落在调用点）。
