## 新增需求

### 需求:对齐Kotlin的源文件收集流程
前端必须采用与 Kotlin 编译器等价的 source roots 收集流程，包括去重、过滤与顺序稳定性。

#### 场景:重复根路径
- **当** content roots 中包含重复或等价路径
- **那么** 系统必须去重并报告重复根路径的诊断信息

#### 场景:非源文件扩展
- **当** content roots 中包含非源文件
- **那么** 系统必须过滤掉不支持的文件扩展，并仅保留可识别的源文件

### 需求:平台源与公共源拆分
系统必须根据 content roots 中的元信息，将源文件划分为平台源与公共源。

#### 场景:标记为公共源
- **当** 某个 source root 被标记为公共源
- **那么** 该 root 下的源文件必须进入“公共源”集合

#### 场景:未标记为公共源
- **当** 某个 source root 未标记为公共源
- **那么** 该 root 下的源文件必须进入“平台源”集合

### 需求:模块级分组
系统必须支持按模块名对源文件进行分组，以支持多模块与依赖分析。

#### 场景:root 指定模块名
- **当** source root 携带模块名信息
- **那么** 该 root 下的源文件必须进入对应模块分组

### 需求:可扩展的源文件收集点
系统必须提供扩展点，允许编译器扩展在收集阶段追加源文件。

#### 场景:扩展追加源文件
- **当** 扩展提供额外的源文件集合
- **那么** 系统必须将其并入最终源文件集合并参与后续解析
