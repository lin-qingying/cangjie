## 新增需求

### 需求:BODY_RESOLVE 阶段必须完成表达式类型与调用绑定
系统必须在 BODY_RESOLVE 阶段完成表达式类型求值、调用候选选择与引用目标绑定，禁止以占位逻辑跳过函数体语义。

#### 场景:函数调用绑定成功
- **当** 函数体存在重载调用与成员访问链
- **那么** BODY_RESOLVE 阶段必须选择正确目标并产出稳定表达式类型

### 需求:BODY_RESOLVE 阶段必须覆盖控制流表达式语义
系统必须支持 if/match/loop 等控制流表达式类型合并与分支一致性检查。

#### 场景:match 分支类型合并
- **当** match 表达式包含多个分支并返回不同候选类型
- **那么** BODY_RESOLVE 阶段必须计算统一结果类型或产出不兼容诊断

### 需求:BODY_RESOLVE 阶段必须覆盖仓颉特有表达式语义
系统必须支持仓颉特有表达式（包括 `spawn`）的语义解析与类型规则，禁止全部降级为错误占位。

#### 场景:spawn 表达式语义解析
- **当** 函数体包含 spawn 表达式
- **那么** BODY_RESOLVE 阶段必须产出可被 CHECKERS 消费的语义信息与必要诊断

### 需求:BODY_RESOLVE 阶段必须保留错误恢复与可继续解析能力
系统必须在局部表达式失败时保留错误表达式节点并继续解析同一函数体其他节点。

#### 场景:局部表达式错误不中断函数体解析
- **当** 函数体中某个表达式解析失败
- **那么** BODY_RESOLVE 阶段必须继续解析剩余表达式并收集完整诊断
