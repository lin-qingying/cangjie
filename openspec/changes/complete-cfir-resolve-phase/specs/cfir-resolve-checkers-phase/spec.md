## 新增需求

### 需求:CHECKERS 阶段必须执行 resolve 终态规则检查
系统必须在 CHECKERS 阶段执行 resolve 范围的最终规则检查，禁止将其退化为仅“标记结束阶段”。

#### 场景:到达 CHECKERS 后产出终态诊断
- **当** 声明推进到 CHECKERS
- **那么** 系统必须完成 resolve 范围最终诊断收敛并可供外部消费

### 需求:CHECKERS 阶段必须基于前序阶段结果执行
系统必须依赖 BODY_RESOLVE 及之前阶段产出的语义结果执行检查，禁止在 CHECKERS 重复做完整类型求值。

#### 场景:CHECKERS 不重复求值
- **当** 前序阶段已完成语义解析
- **那么** CHECKERS 必须直接消费现有语义数据并保持与前序阶段一致

### 需求:CHECKERS 诊断输出必须稳定可比较
系统必须保证 CHECKERS 输出在相同输入下顺序与内容稳定，便于 golden 回归。

#### 场景:重复执行输出一致
- **当** 在相同输入上多次执行到 CHECKERS
- **那么** 诊断条目顺序和文本必须一致
