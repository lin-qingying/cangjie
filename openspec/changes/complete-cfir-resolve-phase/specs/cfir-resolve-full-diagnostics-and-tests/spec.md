## 新增需求

### 需求:resolve 诊断测试必须覆盖完整阶段与真实输入
系统必须提供基于真实 `.cj` 输入的阶段化测试矩阵，覆盖 `IMPORTS` 至 `CHECKERS` 的关键行为，禁止只使用合成声明或单点 smoke case 作为验收标准。

#### 场景:阶段矩阵测试可验证完整语义
- **当** 执行 `cfir:cfir-tree:test` 中 resolve 测试套件
- **那么** 测试必须覆盖声明解析、类型解析、隐式推断、函数体解析与最终检查，并对阶段结果进行断言

### 需求:诊断 golden 输出必须稳定且可回归
系统必须输出稳定可比较的诊断 golden 格式，包含文件、阶段、诊断计数与诊断条目；禁止输出受遍历顺序波动影响的不稳定结果。

#### 场景:同一输入重复执行得到一致输出
- **当** 在同一代码输入上重复运行 resolve 诊断测试
- **那么** 生成的 diagnostics 文本必须一致，除非源码或规则发生变更

### 需求:Analysis API 端到端必须可消费完整 resolve 结果
系统必须验证 `CaCfirResolveFacade` 在目标阶段解析后可被 Analysis API 消费，包括诊断读取与阶段保证，禁止只验证 facade 调用不抛错。

#### 场景:Analysis API 调用可观察完整结果
- **当** 通过 Analysis API 调用 `resolveTo(file, CHECKERS)`
- **那么** 调用方必须能够读取完整诊断集合并观察到声明达到目标阶段，且行为与直接 processor 调用一致

### 需求:迁移期间必须保留最小兼容回归保护
系统必须在迁移正式实现过程中保留兼容层回归测试，确保旧入口不会在过渡期静默失效。

#### 场景:兼容入口在迁移阶段受保护
- **当** 旧的 minimal 入口仍被测试或工具链间接调用
- **那么** 系统必须通过显式兼容测试保证其行为可预期，并给出迁移指引
