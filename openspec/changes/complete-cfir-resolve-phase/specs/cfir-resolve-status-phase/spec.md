## 新增需求

### 需求:STATUS 阶段必须规范化声明状态
系统必须在 STATUS 阶段完成声明修饰符、可见性与状态约束规范化，禁止将状态合法性检查推迟到 CHECKERS。

#### 场景:非法修饰符组合
- **当** 声明出现互斥修饰符组合
- **那么** STATUS 阶段必须产出对应诊断

### 需求:STATUS 阶段必须完成可见性约束检查
系统必须在 STATUS 阶段检查声明可见性与引用范围约束，确保后续阶段基于合法可见性上下文执行。

#### 场景:声明可见性不满足上下文约束
- **当** 声明可见性与所在上下文要求冲突
- **那么** STATUS 阶段必须产出可见性诊断

### 需求:STATUS 阶段输出必须对 EXTENSIONS 与 IMPLICIT_TYPES 可直接消费
系统必须保证 STATUS 产出的声明状态可被 EXTENSIONS 和 IMPLICIT_TYPES 直接使用，禁止后续阶段重复推导声明状态。

#### 场景:后续阶段不重复推导状态
- **当** 声明已完成 STATUS
- **那么** EXTENSIONS 与 IMPLICIT_TYPES 必须直接消费标准化状态并保持一致行为
