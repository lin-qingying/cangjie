## 新增需求

### 需求:IMPORTS 阶段必须完成导入绑定
系统必须在 IMPORTS 阶段完成 import 声明到包、类型、可调用符号的绑定，禁止将导入解析延后到后续阶段。

#### 场景:普通导入成功绑定
- **当** 文件包含有效的包导入、别名导入和多符号导入
- **那么** IMPORTS 阶段必须为后续解析准备可查询的导入绑定结果

### 需求:IMPORTS 阶段必须诊断非法导入
系统必须在 IMPORTS 阶段诊断不存在导入目标、重复导入冲突和别名冲突，禁止将该类错误静默保留到 CHECKERS。

#### 场景:导入目标不存在
- **当** import 指向不存在的包或符号
- **那么** IMPORTS 阶段必须立即产出对应诊断

#### 场景:别名冲突
- **当** 同一文件中两个 import 使用相同别名但指向不同目标
- **那么** IMPORTS 阶段必须产出冲突诊断并保持后续阶段可继续执行

### 需求:IMPORTS 阶段输出必须对 total/lazy resolve 一致可见
系统必须保证 total resolve 与 lazy resolve 在同一文件上可观察到一致的导入绑定结果。

#### 场景:两种模式下导入绑定一致
- **当** 同一文件分别通过 total resolve 与 lazy resolve 推进到 IMPORTS
- **那么** 导入表、导入冲突诊断和可见符号集合必须一致
