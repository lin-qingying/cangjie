## 新增需求

### 需求:按语法域组织 rawBuilder 测试目录
系统必须将 `cfir/raw-cfir/psi2cfir/testData/rawBuilder` 重构为按语法域分层的目录结构，使每类仓颉语法都能被独立定位和维护。

#### 场景:声明与表达式分层可定位
- **当** 开发者需要为某个声明语法新增测试
- **那么** 开发者必须可以在声明语法目录下定位该类别用例，而无需扫描表达式目录

#### 场景:仓颉特性目录独立
- **当** 开发者需要维护仓颉特有语法（如 `extend`、`match`、`spawn`、`VArray`）
- **那么** 必须存在独立语法域或明确子目录承载此类用例

### 需求:语法转换用例必须覆盖核心与错误恢复路径
系统必须为每个已支持的语法节点提供至少一个成功转换场景，并为关键缺失/不完整语法提供错误恢复场景。

#### 场景:成功转换最小样例
- **当** 某语法节点在 `PsiRawCfirBuilder` 中有转换分支
- **那么** 必须存在最小 `.cj` 输入及对应 golden 输出验证转换结果

#### 场景:不完整语法恢复
- **当** 输入包含缺失操作数、缺失条件或缺失表达式等不完整结构
- **那么** 测试必须验证 rawBuilder 输出可稳定渲染且不崩溃

### 需求:测试资产命名和配套文件必须一致
系统必须对 rawBuilder 用例采用统一命名规则，且 `.cj` 与 golden 文件配套关系必须可机器校验。

#### 场景:同名配套校验
- **当** 测试扫描 `testData/rawBuilder` 时
- **那么** 每个测试输入都必须能解析出同名 `.txt`，并按需要存在 `.lazyBodies.txt`

#### 场景:非法命名阻断
- **当** 新增文件不符合命名规则或未提供必要 golden
- **那么** 测试流程必须给出失败信号并提示修复

### 需求:必须维护语法覆盖矩阵
系统必须维护“语法节点到测试文件”的覆盖矩阵，用于检查覆盖缺口并约束新增语法同步补测。

#### 场景:新增语法节点时的门禁
- **当** `PsiRawCfirBuilder` 新增语法节点转换逻辑
- **那么** 变更必须同步更新覆盖矩阵并新增或更新对应测试文件

#### 场景:覆盖缺口检测
- **当** 运行 `:cfir:raw-cfir:psi2cfir:test`
- **那么** 系统必须能够报告矩阵声明存在但缺失测试资产的语法项
