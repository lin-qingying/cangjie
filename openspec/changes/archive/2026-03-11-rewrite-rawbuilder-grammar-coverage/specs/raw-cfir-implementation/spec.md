## 新增需求

### 需求:rawBuilder 必须作为 Raw CFIR 语法转换的规范性测试入口
`raw-cfir:psi2cfir` 必须将 `testData/rawBuilder` 作为语法转换验证的主入口，并要求新增语法转换能力以该入口补齐验证。

#### 场景:新增转换逻辑联动测试
- **当** 开发者为 `PsiRawCfirBuilder` 增加新的语法转换分支
- **那么** 代码评审与 CI 必须要求在 rawBuilder 中补齐对应测试资产

## 修改需求

### 需求:Raw CFIR 构建阶段必须提供可审计的语法覆盖
Raw CFIR 构建阶段测试必须从“样例驱动”升级为“语法覆盖驱动”，并且覆盖状态必须可审计与可追踪。

#### 场景:覆盖状态可审计
- **当** 维护者审查 Raw CFIR 测试质量
- **那么** 维护者必须能够通过目录结构和覆盖矩阵快速识别已覆盖语法与缺口

#### 场景:迁移期间保持回归能力
- **当** 旧样例迁移到新目录结构
- **那么** 测试体系必须持续可运行，并在每次迁移后保持 `:cfir:raw-cfir:psi2cfir:test` 可通过

### 需求:Raw CFIR golden 测试资产必须遵循一致约束
Raw CFIR golden 测试文件必须遵循统一命名、同名配套和最小样例优先原则，禁止以历史遗留方式新增无分类或多语义混杂样例。

#### 场景:新增样例遵循分类
- **当** 开发者新增 rawBuilder 测试
- **那么** 新样例必须放置在对应语法域目录，且用例名称表达单一语法目标

#### 场景:多语义样例受限
- **当** 一个样例覆盖多个语法点且导致 golden diff 难以定位
- **那么** 维护者必须将其拆分为多个最小样例或仅保留必要组合场景
