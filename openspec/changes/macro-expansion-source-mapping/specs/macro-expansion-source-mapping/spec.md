# macro-expansion-source-mapping

## 新增需求

### 需求:宏展开源映射的只读查询

分析层**必须**提供只读的「位置 → 宏展开源映射」查询：对给定元素或偏移，返回该位置所在展开面的身份、其源区间与其可靠性（可靠 / 不可靠或未解析 / 无展开）。查询**禁止**暴露展开产物本身，`MacroSurface*` 不进 CFIR 的边界不得因此改变。

#### 场景:可靠展开内可定位

- **当** 位置落在某个已可靠展开的宏调用区间内
- **那么** 查询返回该展开面的身份与 `sourceRange`，可靠性为「可靠」

#### 场景:不可靠展开如实报告

- **当** 该展开面的载体通道处于未解析状态
- **那么** 查询**必须**返回「不可靠」，**禁止**按启发式把它当作可靠

#### 场景:嵌套宏取最内层

- **当** 同一偏移同时落在外层与内层两个展开面区间内
- **那么** 返回**最内层**展开面的映射；无法唯一确定时返回「不可靠」

#### 场景:无展开时为空

- **当** 位置不在任何宏调用区间内
- **那么** 查询返回「无展开」（与「不可靠」可区分）

### 需求:补全侧的映射消费

补全在**可靠展开**的内容内时，候选来源**必须**限定为「展开自身可见的名字 + 宏调用处作用域」；映射为「不可靠」或「无展开」时，候选来源与行为**必须**与引入本需求之前逐字一致。

#### 场景:可靠展开内的候选来源受限

- **当** 位置在可靠展开的内容内，且工作区里存在与展开无关的同前缀名字
- **那么** 这些无关名字**禁止**出现在候选里

#### 场景:映射缺失时行为不变

- **当** 位置在宏调用内但映射不可靠或无展开
- **那么** 候选集合与排序**必须**与引入本需求之前一致（现有的「宏位置不产出无关候选」用例继续通过）

#### 场景:两端一致

- **当** 同一位置经 IDE 与 LSP 两端补全
- **那么** 两端的候选集合**必须**一致
