## ADDED Requirements

### 需求:CHIR 到 LLVM IR 的全量 lowering
编译器必须实现覆盖核心语言语义的 `CHIR -> LLVM IR` lowering，至少包括函数、调用约定、控制流、类型映射、内存访问、常量与运行时入口，禁止仅生成部分可运行 IR。

#### 场景:函数与控制流 lowering
- **当** CHIR 包含条件分支、循环与函数调用
- **那么** 生成的 LLVM IR 必须包含语义等价的基本块、分支与调用指令

#### 场景:类型与内存 lowering
- **当** CHIR 包含复合类型与地址读写语义
- **那么** LLVM IR 必须生成一致的类型定义、分配与读写指令，且类型宽度与对齐规则必须正确

### 需求:代码生成阶段化与可验证
编译器必须将 lowering 划分为明确阶段并保留中间可检查点，以支持定位差异与回归验证。

#### 场景:阶段输出可审计
- **当** 开发者开启后端调试或测试模式
- **那么** 每个关键 lowering 阶段必须提供可追踪输出或日志，能够定位从 CHIR 到 LLVM IR 的转换差异

### 需求:不支持语义的显式失败
对于未支持的 CHIR 语义，编译器必须返回结构化诊断并停止产物生成，禁止静默降级或输出错误 IR。

#### 场景:遇到未实现语义
- **当** lowering 处理尚未支持的 CHIR 节点
- **那么** 编译器必须报告明确诊断，并且不生成最终 LLVM IR 文件
