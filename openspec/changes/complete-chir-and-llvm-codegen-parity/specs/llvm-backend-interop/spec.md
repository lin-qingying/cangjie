## ADDED Requirements

### 需求:LLVM Backend API 抽象
编译器必须提供统一的 LLVM 后端访问抽象，业务层必须通过抽象接口调用 LLVM 能力，禁止直接耦合 JNI/JNA 细节。

#### 场景:替换后端实现
- **当** 在不同平台或配置下切换 JNI/JNA 实现
- **那么** CHIR lowering 与代码生成业务逻辑不需要修改即可继续工作

### 需求:本地 LLVM 库加载与版本自检
编译器必须在初始化阶段加载本地 LLVM 依赖并执行版本/符号可用性检查，不满足要求时必须给出可操作的诊断。

#### 场景:LLVM 版本不匹配
- **当** 运行环境中的 LLVM 版本或导出符号不满足要求
- **那么** 编译器必须在后端初始化阶段失败，并输出包含期望版本与实际版本的诊断

### 需求:与参考编译器 LLVM IR 产物一致性验证
编译器必须提供自动化验证能力，对同一输入比较 Kotlin 实现与 `external/cangjie_compiler` 的 LLVM IR，并以“完全一致”为通过标准。

#### 场景:一致性通过
- **当** Kotlin 后端生成的 LLVM IR 与参考产物完全一致
- **那么** 一致性测试必须通过并记录通过样例

#### 场景:一致性失败
- **当** 两者在结构或文本稳定化后仍存在差异
- **那么** 测试必须失败并输出可定位的差异报告
