## 新增需求

### 需求：IDE 工具显式采集

系统必须将 CFIR 阶段采集实现为 IDE 工具的显式操作。普通 CFIR 和 Analysis 请求不得检查工具状态、创建轨迹上下文、生成快照或写入可视化工件。

#### 场景：工具未运行

- **当** 用户正常编辑代码、触发补全、导航或 Analysis API 请求
- **那么** 这些路径不调用可视化采集器，也不承担可视化专用工作

#### 场景：用户运行工具

- **当** 用户在 Tool Window 中选择“分析当前文件”
- **那么** IDE 工具在后台读操作中显式调用现有 Low-level CFIR API，并在完成后保存本地 `.cjtrace` 工件

### 需求：记录当前文件的 CFIR resolve 阶段

系统必须通过已有公开 Low-level CFIR API 取得当前文件的 raw CFIR，并按 `CfirResolvePhase` 顺序显式请求每个阶段。每个事件必须记录阶段、耗时、目标和完成结果。

#### 场景：阶段尚未解析

- **当** 工具请求的阶段尚未完成
- **那么** runner 计量该阶段推进，并在阶段边界生成不可变 CFIR 快照

#### 场景：阶段已有缓存

- **当** CFIR 文件已经达到该阶段或更高阶段
- **那么** 工件标记 `alreadyResolved` 和当前阶段，不将缓存命中描述为实际阶段执行

### 需求：记录 diagnostics checker 集合

系统必须分别查询默认、额外和实验性 checker 集合，并记录各自的时长、结果和已冻结诊断。

#### 场景：运行 checker 集合

- **当** 工具对当前文件执行一类 checker 查询
- **那么** 工件包含独立的 checker 事件及该查询返回的诊断位置、名称、级别和消息

### 需求：生成不可变 CFIR 快照

系统必须在每个阶段操作完成后，将 CFIR 转换为不持有 PSI、symbol 或 CFIR 对象的不可变节点树，并保留节点种类、父子关系、resolve 状态和可用源码范围。

#### 场景：比较两个阶段

- **当** 用户选择同一文件的两个阶段快照
- **那么** 检查器展示新增、移除和变化的节点及语义字段

#### 场景：合成节点没有源码范围

- **当** CFIR 节点没有源位置
- **那么** builder 使用父节点路径和同类序号生成稳定节点 ID

### 需求：图形化浏览快照

系统必须在 IDE 中以可滚动有向图呈现 CFIR 节点的父子关系，并提供树、渲染文本和阶段差异视图。

#### 场景：查看 CFIR 关系图

- **当** 用户选择一个阶段快照
- **那么** 关系图显示节点和父子连线，点击节点可选择源码范围

### 需求：本地工件回放

系统必须支持保存并重新打开版本化 UTF-8 `.cjtrace` 工件，且可导航回可用源码位置。

#### 场景：打开无效工件

- **当** 用户打开损坏 JSON 或未知 schema 版本
- **那么** 检查器显示具体错误并拒绝加载部分工件

### 需求：限制快照开销

系统必须限制单次快照的节点数和渲染文本长度，并在工件中显示被省略或截断的信息。

#### 场景：超过快照预算

- **当** 快照达到节点或文本上限
- **那么** builder 停止扩大快照并在文本或元数据中标记截断状态
