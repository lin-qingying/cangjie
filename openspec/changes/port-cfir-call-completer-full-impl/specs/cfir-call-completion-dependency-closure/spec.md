## 新增需求

### 需求:调用补全依赖闭包完整迁移
系统必须将 `CfirCallCompleter` 所需的接口、抽象类、上下文对象、辅助组件及相关文件完整迁移或在 CFIR 中重建，禁止遗漏导致运行期或编译期缺失依赖。

#### 场景:依赖闭包无缺口
- **当** 基于迁移清单逐项验证调用补全依赖
- **那么** 每个被 `CfirCallCompleter` 直接或间接引用的类型都必须在项目内有实现或等价重建

#### 场景:已有不完整声明被修正
- **当** 项目中存在与上游目标不一致或不完整的相关 `Cfir*` 声明
- **那么** 这些声明必须在本变更中被修正至满足调用补全依赖契约

### 需求:依赖声明必须完整迁移
系统必须完整迁移调用补全链路所需依赖声明，包括源码导入依赖、模块依赖及类型引用依赖，禁止“缺依赖后补洞式”实现。

#### 场景:依赖声明完整且可审计
- **当** 对照迁移清单审查调用补全相关文件
- **那么** 每个上游依赖声明都必须在本项目中存在对应声明、替代声明或记录为不适用并附理由

### 需求:移除 K1 调用解析接入
系统必须移除对 `org.jetbrains.kotlin.resolve.calls` 等 K1 调用解析包的接入；若存在必要能力，必须在 `cfir` 命名空间提供等价实现并由调用补全过程使用。

#### 场景:代码中不存在 K1 调用解析包引用
- **当** 扫描调用补全相关模块的导入与类型引用
- **那么** 不得出现 `org.jetbrains.kotlin.resolve.calls` 包下符号的直接依赖

#### 场景:必要能力在 CFIR 内可用
- **当** 调用补全过程需要原 K1 侧能力
- **那么** 系统必须使用 `cfir` 命名空间内的等价接口或实现完成同等职责
