## 上下文

本变更目标是在仓颉编译器中移植 Kotlin FIR `FirCallCompleter` 及其依赖实现，且保持“实现闭包完整”而非最小可运行版本。当前项目已有部分 CFIR 调用解析声明，但与上游行为和分层关系存在偏差或缺失。  
同时，仓库约束要求接口优先、模块边界清晰、避免泄露实现细节；用户明确要求删除 K1（`org.jetbrains.kotlin.resolve.calls`）相关接入，并统一使用 `cfir` 前缀。  
本阶段只交付补全器及依赖基础设施，不修改 `CFirExpressionsResolveTransformer` 的调用路径接线。

## 目标 / 非目标

**目标：**
- 在 CFIR 体系中提供语义等价的 `CfirCallCompleter` 及其直接/间接依赖实现，确保依赖闭包完整。
- 对现有不完整或不准确的相关接口/抽象进行对照修正，并保持 `Cfir*` 命名体系一致性。
- 移除或替换所有 K1 调用解析包耦合，必要能力在 `cfir` 命名空间重建。
- 形成可独立构建与可测试的调用补全基础设施，为后续接线预留清晰扩展点。
- 形成“上游符号 -> 本仓符号”的逐项追溯矩阵，覆盖方法、接口、抽象、具体类与依赖声明。

**非目标：**
- 本阶段不将 `CfirCallCompleter` 接入 `CFirExpressionsResolveTransformer`。
- 不在本阶段重构无关调用解析流程或做性能优化专项。
- 不引入与调用补全无关的新语言特性或诊断策略变更。

## 决策

### 决策 1：采用“上游结构保真迁移 + CFIR 命名映射”策略
- 选择：尽量保持 Kotlin FIR 原始结构与行为语义，仅做包名、类型名、依赖入口的 CFIR 化映射。
- 理由：该策略可减少行为漂移，降低后续与上游对照维护成本。
- 备选方案：
  - 方案 A：按当前仓库抽象重新设计最小实现。  
    放弃原因：与用户“禁止最小实现、复制粘贴级”的约束冲突，且易引入语义缺口。
  - 方案 B：仅迁移核心类，依赖按需补齐。  
    放弃原因：无法保证依赖闭包完整，后续整合风险高。

### 决策 2：按“接口层 -> 抽象层 -> 具体实现”顺序迁移
- 选择：先补齐跨模块 SPI 接口，再迁移抽象基类与上下文结构，最后落地具体补全器与协作组件。
- 理由：符合项目接口优先架构，减少循环依赖与临时适配层。
- 备选方案：
  - 方案 A：先迁移具体实现后反推接口。  
    放弃原因：会放大返工面，易污染模块边界。

### 决策 3：K1 依赖“零容忍”并在 CFIR 内重建必要能力
- 选择：对 `org.jetbrains.kotlin.resolve.calls` 相关符号做全面排查，逐项替换为 CFIR 版本。
- 理由：避免旧前端语义泄露，确保调用补全基础设施可在 CFIR 语境下独立演进。
- 备选方案：
  - 方案 A：短期保留桥接适配。  
    放弃原因：用户明确禁止；且桥接会造成长期技术债。

### 决策 4：显式保留“未接线”边界
- 选择：为后续 transformer 接线预留入口，但在本变更中不触发执行路径变更。
- 理由：降低一次性改动风险，便于先完成基础设施正确性验证。
- 备选方案：
  - 方案 A：同步完成接线。  
    放弃原因：测试和回归面显著扩大，不符合当前变更范围。

### 决策 5：禁止自主实现，采用“源码对位迁移”验收
- 选择：对 `FirCallCompleter` 及其依赖采用源码级对位迁移，禁止从零设计替代实现。
- 理由：确保语义保真与长期可维护性，避免“看似可用但行为偏移”的隐性风险。
- 备选方案：
  - 方案 A：保留上游语义，仅自主重写实现。  
    放弃原因：不可验证地引入差异，不满足本变更强约束。

## 风险 / 权衡

- [风险] 上游依赖链过长导致遗漏文件或接口不匹配  
  -> 缓解措施：按依赖图分批迁移并在每批后执行模块级编译检查，建立迁移清单逐项勾选。
- [风险] 现有 CFIR 声明与迁移目标冲突，产生破坏性改名或签名调整  
  -> 缓解措施：先做对照表，采用“兼容层短期保留 + 调用点分批切换”策略（仅限 CFIR 内部）。
- [风险] 无接线状态下难以验证端到端行为  
  -> 缓解措施：增加结构级与单元级测试（API 合同、候选补全规则、诊断产物）并使用黄金数据对齐。
- [风险] 复制级迁移带来代码量增长  
  -> 缓解措施：严格限定范围在调用补全与依赖闭包，避免顺手重构。
- [风险] 团队在迁移中不自觉引入“自主改写”  
  -> 缓解措施：引入追溯矩阵审查门禁，所有新增/改动符号必须有上游映射依据。

## 迁移计划

1. 梳理 Kotlin `FirCallCompleter` 依赖闭包，形成“源符号 -> CFIR 目标符号”映射清单。  
2. 建立迁移门禁：未在映射清单登记的新增实现不得进入主分支。  
3. 先迁移/修正跨模块接口与抽象，再迁移核心实现类与辅助组件。  
4. 消除 K1 包引用并在 CFIR 命名空间重建必要类型。  
5. 补充/更新测试，验证编译通过与关键语义一致。  
6. 保持 `CFirExpressionsResolveTransformer` 无接线变更，输出后续接线待办项。  

回滚策略：
- 以提交粒度分阶段推进；若出现范围外回归，按阶段回滚最近迁移批次，保留已验证的接口层改动。
