## 上下文

仓库一方模块中存在“乱码/编码破损”的注释风险，影响可读性与维护效率。需要在不影响业务逻辑的前提下，建立可重复的扫描与修复流程，覆盖常见注释文件类型，并排除 external/。

## 目标 / 非目标

**目标：**
- 识别并修复一方模块中所有注释乱码（排除 external/）。
- 建立可审计的修复清单与校验流程，确保遗漏可被发现。
- 不改变运行逻辑与对外 API。

**非目标：**
- 不进行大规模重构或格式化。
- 不翻译或改写正常注释语义，仅修复乱码。
- 不触及 external/ 目录。

## 决策

- 采用“扫描清单 + 逐条修复”的流程，避免批量重编码带来的误伤风险。
  - 备选方案：人工全量巡检（覆盖差、耗时高）、全量转码（风险高）。
- 扫描范围包含常见注释载体（Kotlin/Gradle/Markdown/测试等），并对注释上下文进行过滤，减少误报。
- 修复以“最小改动、语义保持”为原则，仅修正乱码字符，避免引入新的格式化噪声。

## 风险 / 权衡

- [误报] → 采用注释上下文与多种乱码特征组合筛选，并进行人工确认。
- [漏报] → 扩展特征集与文件类型覆盖范围，提供复查清单。
- [语义误改] → 逐条对照上下文修正，确保原意不变。
