## 新增需求

### 需求:全诊断定义覆盖台账
系统必须以 `CfirDiagnosticsList` 中的全部诊断定义为唯一基线，建立不遗漏任何诊断名的覆盖台账。

#### 场景:盘点全部诊断定义
- **当** 变更进入规划、实施或验收阶段
- **那么** 必须能列出 `CfirDiagnosticsList` 中全部诊断定义
- **并且** 每个诊断定义都必须拥有唯一的覆盖记录

### 需求:诊断责任层唯一归属
系统必须为每个诊断定义指定唯一责任层，并禁止跨层兜底。

#### 场景:诊断归属为 resolve
- **当** 某个诊断依赖候选选择、参数绑定、约束求解、未解析恢复或深层泛型推断收敛
- **那么** 该诊断必须归属到 resolve 管线
- **并且** 不得通过 checker 做兜底实现

#### 场景:诊断归属为 checker
- **当** 某个诊断属于声明、表达式、类型、平台注解、互操作或语言特性层面的后置语义约束
- **那么** 该诊断必须归属到 checker 管线
- **并且** 必须在 declaration / expression / type checker 体系中实现

### 需求:覆盖率说明可审计
系统必须产出可审计的诊断覆盖率说明。

#### 场景:查询提案覆盖率
- **当** 开发者查看该变更的状态
- **那么** 必须能够知道诊断总数、已覆盖数、resolve 负责数、checker 负责数、剩余数
- **并且** 每个剩余诊断都必须能映射到具体子任务

### 需求:未完成诊断不得脱离任务树
系统必须保证所有未完成诊断都进入任务树，不允许遗漏。

#### 场景:存在未覆盖诊断
- **当** 某个诊断尚未完成实现或验证
- **那么** 它必须拥有明确的子任务、阻塞说明和验证入口
- **并且** 不得以“后续再处理”但无任务映射的方式留空
