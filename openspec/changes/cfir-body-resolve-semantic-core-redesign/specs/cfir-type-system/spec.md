## 新增需求

### 需求:保留统一类型表示
CFIR 类型系统必须保留 `ConeCangJieType` 作为统一类型表示根，不得引入平行的 `CfirType*` 类型表示层替代现有根类型。

#### 场景:类型表示根保持稳定
- **当** 系统重构 `BODY_RESOLVE` 的类型关系与约束体系
- **那么** `ConeCangJieType` 仍必须作为 CFIR 统一类型表示根保留

### 需求:稳定具体类型保留
系统必须保留已稳定承载仓颉真实语义的主要 `Cone*` 具体类型，包括基础类型、类类型、结构体类型、枚举类型、函数类型、元组类型、数组类型、联合类型、交叉类型、`QuestTy` 和错误类型。

#### 场景:真实语义类型继续沿用 Cone 表示
- **当** 系统表示仓颉真实语义类型
- **那么** 必须继续使用稳定的 `Cone*` 具体类型，而不是为其创建平行类型层

### 需求:类型关系分级结果
类型系统必须提供比单纯 `isSubtype` 更丰富的类型关系分级结果，用于支持类型兼容性判断、重载排序、理想数值类型处理和 `QuestTy` 回退。

#### 场景:类型比较输出分级结果
- **当** 系统比较两个类型之间的关系
- **那么** 必须返回可区分完全相同、子类型、可转换兼容、可通过变量约束收敛以及不兼容的结果

### 需求:占位与过渡类型重构
系统必须重新规划 `ConeStubType`、`ConeCapturedType` 及相关推断中间类型的职责边界，并将其视为过渡实现或待替换抽象，而不是长期核心语义类型。

#### 场景:中间推断类型降级
- **当** 系统表示占位类型、延迟分析类型或捕获式中间类型
- **那么** 必须明确其仅用于推断过程，且不得继续充当长期稳定的真实语义类型

### 需求:类型变量状态与引用分离
类型系统必须将类型变量的求解状态与类型图中的引用表示分离，不得继续把变量状态本身伪装成普通具体类型。

#### 场景:类型变量参与求解
- **当** 某个类型变量参与候选局部求解
- **那么** 系统必须将变量状态保存在独立状态对象中，并在类型图中仅保留变量引用视图
