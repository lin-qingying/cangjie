## 新增需求

### 需求:BODY_RESOLVE 统一语义核心
CFIR 的 `BODY_RESOLVE` 必须提供统一的语义核心，用于承载表达式类型合成、期望类型检查、候选局部求解、调用补全、重载排序输入和结果写回。

#### 场景:表达式解析进入统一语义核心
- **当** `BODY_RESOLVE` 解析表达式、调用表达式或控制流表达式
- **那么** 系统必须通过统一的 BODY 语义核心推进类型合成、约束传播与候选处理

### 需求:双向类型检查
`BODY_RESOLVE` 必须支持自底向上的类型合成和受期望类型驱动的自顶向下检查，并且两者必须共享同一套类型关系与约束语义。

#### 场景:期望类型驱动检查
- **当** 某个表达式处于带期望类型的上下文中
- **那么** 系统必须先进行类型关系判断，并在需要时把期望类型转化为约束参与候选局部求解

### 需求:候选局部求解
对每个调用候选，系统必须建立独立的局部求解状态，不得将不同候选的类型变量、约束和补全状态直接混用。

#### 场景:多候选调用解析
- **当** 一个调用点存在多个可行候选
- **那么** 系统必须为每个候选分别进行局部求解，并据此生成候选可比结果

### 需求:调用补全直接接入
`CfirCallCompleter` 必须能够直接接入新的 BODY 语义体系，并消费候选局部求解结果完成结果写回。

#### 场景:调用补全写回结果
- **当** `CfirCallCompleter` 对某个候选执行调用补全
- **那么** 系统必须返回结果类型、类型参数映射、未解变量信息和约束问题，供 CFIR 写回使用

### 需求:transformer 架构边界稳定
新的 BODY 语义核心必须保留 `CfirAbstractBodyResolveTransformer` / dispatcher 的遍历与分发外壳，同时允许其内部组件装配关系被重构。

#### 场景:保留 transformer 外壳
- **当** 新语义核心接入 `BODY_RESOLVE`
- **那么** 系统必须保留 transformer / dispatcher 外壳，不得为此新增平行的 body resolve 框架
