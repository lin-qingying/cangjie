## 新增需求

### 需求:调用解析依赖候选局部求解
CFIR 调用解析必须建立在候选局部求解基础上，不得仅通过简单的类型匹配或单一子类型判断完成候选筛选与选择。

#### 场景:调用点存在多个候选
- **当** 某个调用点存在多个候选函数、属性或可调用目标
- **那么** 系统必须对每个候选分别建立局部求解状态并生成可比较结果

### 需求:调用补全消费候选结果
`CfirCallCompleter` 必须以候选局部求解结果为输入完成调用补全，不得继续直接依赖旧的 Kotlin 风格补全细节和约束存储模型。

#### 场景:CfirCallCompleter 完成候选补全
- **当** `CfirCallCompleter` 处理一个已选候选
- **那么** 系统必须基于候选局部求解结果写回结果类型、类型参数映射和补全相关信息

### 需求:重载排序使用类型关系与约束结果
调用解析中的重载排序必须同时考虑类型关系分级结果、约束收敛情况、`QuestTy` 回退、理想数值类型具体化和 `extend` 参与情况。

#### 场景:重载排序比较两个候选
- **当** 系统需要在两个可行候选之间选择更优目标
- **那么** 系统必须比较参数匹配质量、转换需求、未解变量、`QuestTy` 回退和 `extend` 参与信息，而不能仅比较是否可调用

### 需求:期望类型参与调用求解
带期望类型的调用解析必须允许期望类型进入候选局部约束系统，并影响候选的可行性与排序。

#### 场景:带期望类型的调用
- **当** 一个调用表达式处于带期望类型的上下文中
- **那么** 系统必须把期望类型作为候选局部求解输入，而不是仅在解析完成后做外层检查

### 需求:extend 语义参与调用解析
调用解析必须把 `extend` 语义作为一等输入参与候选过滤、兼容性判断和最终候选选择。

#### 场景:通过 extend 引入候选
- **当** 某个候选依赖 `extend` 语义才可见或才可兼容
- **那么** 系统必须在候选过滤和排序阶段显式考虑 `extend` 参与信息
