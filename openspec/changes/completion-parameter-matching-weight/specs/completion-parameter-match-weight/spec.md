# completion-parameter-match-weight

## 新增需求

### 需求:实参位的期望参数类型推导

当补全位置落在调用表达式的实参内时，分析层**必须**给出该位的期望参数类型：位置实参按其下标取被调方形参的类型；命名实参按形参名取类型；被调方无法唯一确定、下标越界或形参表不可得时**必须**返回「未知」，**禁止**用形状或名字猜测。

#### 场景:位置实参命中

- **当** 位置在 `f(a, <caret>)` 的第二个实参内，且 `f` 的第二个形参类型为 `Int64`
- **那么** 该位的期望类型是 `Int64`，候选排序里类型匹配的候选获得加权

#### 场景:位置实参不匹配

- **当** 该位形参类型为 `Int64`，而候选的类型为 `String`
- **那么** 该候选**不**获得加权（也不被惩罚；排序其余维度不变）

#### 场景:命名实参按名匹配

- **当** 位置在 `f(name: <caret>)` 内，且 `f` 有名为 `name` 的形参
- **那么** 期望类型取该形参的类型

#### 场景:无法确定时返回未知

- **当** 被调方未解析、或实参下标超出形参表、或同名重载使其无法唯一确定
- **那么** 期望类型为「未知」，补全排序不因该维度产生任何变化

#### 场景:无调用上下文时行为不变

- **当** 位置不在任何实参内（赋值右值、return、表达式语句等）
- **那么** 期望类型的推导与接入前的行为**必须**逐字保持不变

### 需求:实参位结论的权重表达

实参位的期望类型结论**必须**复用「期望类型匹配」这一既有维度进入排序：匹配则加权、未知则无影响；**禁止**为此新增权重维度、新增平台 weigher 或改动既有位段的步长约束。

#### 场景:极值不越位

- **当** 低位维度（含参数匹配）取到其极值（`Int.MAX_VALUE`/`MIN_VALUE`）
- **那么** 排序结果**必须**仍由高位维度决定（沿用既有极值验算用例的口径）

#### 场景:两端一致

- **当** 同一候选经 IDE 与 LSP 两端渲染与排序
- **那么** 两端的候选集合与相对顺序**必须**一致
