## 新增需求

### 需求:B1 模块与平台边界
补全 API、共享编辑处理和 CFIR 支持的补全实现必须分层组织。主仓库 code-insight 承载共享语言实现，宿主承载平台接线与装配；禁止在 intellij-ide 新建本地 PSI、类型推断或 Analysis 实现。

#### 场景:装配补全模块
- **当** 产品引入补全制品
- **那么** 所有跨模块能力必须经明确接口消费，业务模块不得依赖实现内部类，K1 描述符实现不得进入 CFIR 补全依赖图

### 需求:B2 原生入口与位置初始化
必须注册针对仓颉语言的原生 IntelliJ 补全入口，区分基础与智能补全，构造原文件/副本/前缀/替换区间，并按仓颉语法修正占位标识符和位置。

#### 场景:手动与自动触发
- **当** 用户手动请求补全或在合法的成员访问位置触发自动补全
- **那么** 平台必须进入仓颉原生管线，并产生语义候选而非仅依赖通用词补全

#### 场景:不完整语法及字符串
- **当** 光标位于未完成的泛型、调用、类型或字符串插值中
- **那么** 占位副本与替换范围必须合法且稳定，原始字符串内不得错误启用插值补全

### 需求:B3 贡献者与执行器
贡献者必须按位置上下文和优先级组织，并通过可取消的执行器提交结果。内部贡献者列表与 IntelliJ 扩展点必须明确区分，禁止为了机械模仿而新增无实际消费者的外部扩展点。

#### 场景:串行执行和取消
- **当** 执行器调度局部、成员和索引候选工作
- **那么** 较快且相关的结果必须先可用，取消必须及时传播，单次错误不得被伪装成完整的空结果

#### 场景:并行执行准入
- **当** 准备启用并行执行
- **那么** 必须先通过会话隔离、确定顺序、取消和串行结果等价测试；在此之前只能使用串行路径

### 需求:B4 候选覆盖与过滤
必须覆盖仓颉适用的局部/参数、成员、继承与 extend、类型、包/import、命名实参、关键字、enum 构造器、声明生成和文档候选。候选必须按上下文、适用性、可见性及遮蔽过滤，禁止仅按显示名称去重。

#### 场景:带接收者的成员补全
- **当** 光标位于已知接收者的成员访问位置
- **那么** 仅返回该类型及适用继承/extend 链上的可用成员，并显示实例化后的签名

#### 场景:未导入及同名候选
- **当** 存在未导入声明和同名重载
- **那么** 必须保留可区分的身份、签名与导入策略，不得混入不可访问的其它工作区局部声明

### 需求:B5 展示数据不泄漏分析生命周期
结果工厂必须将 Analysis 查询结果转换成稳定的展示与插入数据，提供名称、图标、类型、参数和来源。禁止在完成 analyze 后保留裸 CaSession、CaSymbol、CaType 或惰性的分析序列供 UI 使用。

#### 场景:分析后展示和选择
- **当** 分析会话结束后弹窗继续显示或用户选择候选
- **那么** 展示必须使用稳定快照，语义复查必须重新进入分析并恢复指针，失效候选不得修改文档

### 需求:B6 排序及智能补全
排序必须结合期望类型、作用域/接收者来源、导入成本、候选类别和平台排序锚点。智能补全必须对候选实施语义上的期望类型过滤，未知期望类型的降级行为必须有独立测试。

#### 场景:基础与智能结果
- **当** 同一位置请求基础和智能补全且存在确定的期望类型
- **那么** 基础补全保留适用候选并排序，智能补全仅保留可满足该期望类型的结果或明确支持的构造方案

### 需求:B7 插入与导入事务
插入必须在平台写命令内完成，校验文档版本和目标位置，并根据策略保留短名、增加导入或插入限定名后缩短。必须正确处理 Enter/Tab、已有括号、已有实参、caret 和撤销；禁止机械复制 Kotlin 插入语法。

#### 场景:命名参数
- **当** 选择仓颉命名参数候选
- **那么** 只能针对支持命名调用的参数插入仓颉的冒号形式，不能插入 Kotlin 的等号形式

#### 场景:组织名和别名
- **当** 插入需要组织名限定或已有 alias 的声明
- **那么** import 中保留组织名/别名信息，表达式中使用合法名称，不得把组织名前缀复制到表达式访问中

#### 场景:原有调用和撤销
- **当** 用户用 Tab 替换已有调用中的候选并随后撤销
- **那么** 插入不得重复括号或破坏保留实参，撤销必须恢复本次插入及关联导入

### 需求:B8 高级补全与仓颉差异
必须在基础链路之上实现适用的链式补全、构造候选、override/implement、模式/enum 和 CDoc 场景，并复用已有的声明生成服务。每项 Kotlin 独有行为必须记录不适用理由或仓颉替代方案，禁止默认原样移植。

#### 场景:未导入接收者的成员补全
- **当** 当前成员访问的接收者名称尚未解析，但可以找到名称精确匹配的可导入候选
- **那么** 系统必须在有界、可取消的恢复步骤中补齐接收者候选，并复用普通成员补全管线及导入处理
- **并且** 该行为不得被描述为任意长度表达式链搜索；后者不属于本次 Kotlin K2 参考链路的对齐要求

#### 场景:宏与二进制声明
- **当** 补全位置属于宏输入 token、宏展开后可映射的代码或 .cjo 依赖引用
- **那么** 管线必须区分 token 与普通表达式上下文，只使用有可靠源映射和符号身份的语义结果

### 需求:B9 降级与可观测性
必须定义索引不可用、分析受限、请求取消和分析失败时的行为，并记录阶段、耗时和失败类别。索引不可用时允许语法级安全降级，但禁止回退到全工作区扫描或把分析异常全部吞成空列表。

#### 场景:索引构建期间
- **当** IDE 处于不可用索引状态
- **那么** 管线仅提供约定的无需索引候选，不得调用不可用索引服务，并允许后续正常请求取得语义候选

### 需求:B10 制品及生产 XML 接线
必须同时完成主仓库模块/制品和宿主 compileOnly/runtimeOnly、Version Catalog、复合构建替换与责任域 XML 接线。测试必须加载生产描述符，禁止仅手工注册测试 contributor 后宣布接线完成。

#### 场景:真实产品加载
- **当** 产品按当前的 plugin.xml 模块描述符聚合方式加载
- **那么** 仓颉补全 contributor、共享服务和所需资源必须唯一且可解析，正式补全能够被触发并完成插入

#### 场景:兼容平台
- **当** 在项目声明支持的平台基线上验证产品
- **那么** 必须验证补全涉及的 API 与行为兼容性；差异实现必须放入 platform 对应目录，不得在业务逻辑中散布版本分支

### 需求:B11 原生补全验收独立于 LSP
原生补全的验收必须在不依赖 LSP 服务的条件下完成：不得因 LSP 可用而放宽原生候选的验收标准，也不得把 LSP 成功、协议假实现或历史报告视为原生补全已完成。LSP 侧的接入由 `lsp-completion-support` 规格约束，两份规格共用同一候选生成实现。

#### 场景:LSP 不可用
- **当** LSP 未注册或未启动
- **那么** 已启用的原生补全必须独立满足本规格，且不得因此自动修改 LSP 的注册和启动配置

#### 场景:两端共用实现
- **当** 同一位置分别由 IDE 与 LSP 请求补全
- **那么** 两端候选必须来自同一次上游管线；LSP 不得另行实现候选生成或降级扫描

### 需求:B12 测试与发布准入
必须分别验证候选存在/不存在/数量、重载身份、展示字段、排序、插入后文本和 caret、增量失效、生命周期、生产接线。每个任务的完成记录必须关联当前源码下的执行结果。

#### 场景:阶段验收
- **当** 准备将某个补全阶段标为可用
- **那么** 必须具备该阶段正例与反例的新执行记录；只有测试文件、旧 XML 或命令清单时不得标为通过
