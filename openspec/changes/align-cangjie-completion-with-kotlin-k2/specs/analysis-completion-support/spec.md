## 新增需求

### 需求:A1 按位置暴露语义作用域
Analysis API 必须提供由文件与源码位置确定的作用域上下文，包含作用域来源、查找优先级和可用的隐式接收者。上下文必须来自 CFIR/低层分析的语义状态；禁止在 IDE 插件中用全文件 PSI 声明扫描替代词法查找。代码片段（表达式片段、类型片段）必须作为独立的位置种类提供作用域上下文，其片段顶层声明通过共享作用域提供者提供，禁止由补全侧自行收集。

#### 场景:局部声明与遮蔽
- **当** 光标位于包含参数、局部声明、嵌套块和同名外层声明的函数中
- **那么** 作用域结果必须按该位置的真实查找顺序暴露候选，并排除作用域之外的局部声明
- **并且** 候选必须保留符号身份和来源，不得通过名字去重丢失合法重载

#### 场景:继承上下文与隐式接收者
- **当** 光标位于成员函数、嵌套函数或 extend 成员中
- **那么** 上下文必须保留适用的隐式接收者类型与来源；是否可见必须遵守仓颉的静态/实例及访问规则

#### 场景:代码片段作用域
- **当** 光标位于表达式片段或类型片段中（IDE 求值窗口、调试器求值）
- **那么** 片段自身的顶层声明必须作为片段成员作用域参与候选，且与目标文件的可见符号合并
- **并且** 不得泄漏宿主或 IDE 专有符号；片段不得被误建模为仓颉脚本（仓颉无脚本文件这一语言特性）

### 需求:A2 区分文件声明作用域与导入作用域
Analysis API 必须区分文件声明、当前包、显式导入、星号导入和默认导入的视图，并提供可组合的导入/位置作用域。禁止为实现补全而无条件改变既有文件声明作用域的结果集合。

#### 场景:别名及导入优先级
- **当** 文件存在同包声明、导入别名和同名的不同导入来源
- **那么** 组合结果必须保留导入后可用名称及来源优先级，并与编译器的名称解析结果一致
- **并且** 单独查询文件声明作用域时，不得隐式混入其它文件的全部声明

### 需求:A3 保留实例化接收者的成员签名
类型作用域必须保留接收者的实际类型实参、继承替换与适用的 extend 成员信息。公开结果必须允许补全取得替换后的参数和返回类型，禁止只取得原始 class-like 符号后遗失接收者的类型实参。

#### 场景:泛型成员和继承成员
- **当** 对同一泛型类型的不同实例查询成员，且成员来自本类型或泛型父类型
- **那么** 返回的签名必须分别反映各接收者的实际类型，且声明身份可以追溯

#### 场景:非普通类类型
- **当** 接收者为 primitive、元组、函数、typealias 或包含 Option 的合法类型
- **那么** 系统必须使用对应的仓颉类型/extend 规则查询成员；不支持的查询必须显式降级，不能假装得到完整成员集合

### 需求:A4 分离候选适用性与导入可达性
必须为补全提供绑定使用点、原文件、补全副本及接收者的候选适用性检查契约。检查必须复用 CFIR 的类型匹配与泛型约束规则，并能表达适用性及所需类型替换。禁止以现有 DIRECT/REQUIRES_IMPORT/HIDDEN 结果替代适用性检查。

#### 场景:完全实例化与泛型 extend
- **当** 相同名称的成员分别来自完全实例化 extend 和带附加约束的泛型 extend
- **那么** 仅适用于当前接收者的候选可以通过检查，并返回相应签名替换信息
- **并且** 禁止因为成员可导入就忽略类型实参或 where 约束

#### 场景:已有候选判定调用者
- **当** 现有引用缩短或导入规划调用三态候选 API
- **那么** 原有调用入口必须保持兼容，新增适用性能力不得通过无说明的接口删除破坏调用者

### 需求:A5 可见性与可达性服从使用点语义
候选可见性必须与编译器的公共可访问性规则保持一致，并使用文件、声明链、接收者和查找来源。可达性必须考虑词法遮蔽及导入别名；禁止仅因文件级查询曾包含目标符号就断言该短名在任意位置均可直接插入。

#### 场景:访问修饰符与遮蔽
- **当** 当前上下文存在 private/internal/protected 声明、不可访问的 extend 成员或局部同名声明
- **那么** 不可访问的声明必须被过滤，直接插入的名称必须在当前使用点解析到预期目标

#### 场景:需要新增导入
- **当** 候选可以使用但必须新增带组织名或别名的导入
- **那么** 分析结果必须保留精确导入信息，并与表达式实际要插入的名称分开表示

### 需求:A6 补全副本分析与生命周期隔离
必须基于已有游离文件模块基础设施提供受控的补全副本分析入口，明确原文件映射、PREFER_SELF/IGNORE_SELF 行为、失效和缓存边界。禁止把“存在枚举”或“存在包装函数”当作副本语义已验证的证据。

#### 场景:副本与原文件隔离
- **当** 编辑器为未完成语法创建带占位标识符的副本并请求分析
- **那么** 按指定模式查询原文件/副本声明，原文件文本不得改变，失效或取消后不得泄漏旧上下文

#### 场景:并发与嵌套分析
- **当** 不同分析请求使用不同副本或不同解析模式
- **那么** 模式、缓存和线程上下文不得相互污染；异常退出必须恢复先前状态
- **并且** Analysis 会话对象、符号和类型不得作为未受保护的长生命周期 UI 状态保存

### 需求:A7 智能补全所需期望类型
必须在现有表达式类型组件中支持仓颉适用的期望类型场景，包括带类型初始化、赋值、布尔条件、命名参数默认值、返回值和调用实参。必须覆盖不完整调用的可恢复分析；禁止照搬 Kotlin 独有表达式语义。

#### 场景:初始化与赋值
- **当** 光标位于已声明目标类型的初始化表达式或赋值右侧
- **那么** 期望类型必须由目标提供，而非复用当前占位表达式的错误类型

#### 场景:不完整调用
- **当** 调用的实参尚未填写完整或重载尚未唯一确定
- **那么** 系统必须依据可恢复的候选信息取得可确定的期望约束；无法确定时必须明确返回未知，不能伪造确定类型

### 需求:A8 候选发现与符号身份
必须复用声明提供者、索引和分析作用域边界发现未导入声明，并保留重载、构造器、enum 构造器和来源信息。禁止以工作区全部 PSI 声明扫描或 label 去重作为生产补全的默认候选算法。

#### 场景:源码及二进制依赖
- **当** 候选来自源码模块或无源码的 .cjo 依赖
- **那么** 均必须经当前模块可见的提供者和稳定符号身份生成候选，且遵守依赖及导出边界

#### 场景:同名构造器和重载
- **当** 多个合法候选拥有相同名称但不同参数、类型签名或声明身份
- **那么** 候选发现与后续转换不得因显示名称相同而合并它们

### 需求:A9 分析契约具有分层验证
新增或改变的补全语义契约必须通过共享 Analysis 测试基座验证，并覆盖公开 API、CFIR 实现、副本/失效和源码/二进制依赖。禁止以插件界面快照或历史测试报告代替分析层验证。

#### 场景:验收语义 API
- **当** 准备确认某个 Analysis 任务完成
- **那么** 必须提供该版本下新执行的正例、反例和身份/签名断言结果；未运行的测试必须标为未验证
