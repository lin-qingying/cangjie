# Fix Garbled Comments Design

## Goal
在全仓库范围内仅修复“明显乱码/编码错误”的注释文本，保持代码逻辑与行为不变。

## Scope
- **包含**：行注释、块注释、KDoc 中出现明显乱码特征的文本。
- **排除**：可读但表达不佳的注释、不属于注释的字符串或代码、`external/` 目录。

## Approach
1. **扫描**：遍历源码文件，提取注释并匹配乱码特征（如 U+FFFD 替换符、常见乱码片段）。
2. **清单**：产出“文件 + 行号 + 原注释”的修复列表，确保可审计。
3. **修复**：按清单逐条替换为可读注释，保持原意、缩进与格式。
4. **复核**：确认仅注释行发生变更，避免误改代码内容。

## Error Handling
- 无法明确判断为乱码的注释不修改，但记录为“待确认”。
- 文件编码异常时先记录并最小化替换，避免扩大影响。

## Testing & Verification
- 只改注释，不改逻辑。
- 运行涉及模块的基础构建/测试（优先最小范围），确认无回归。

## Risks
- 误判导致修改了本可保留的注释文本。
- 扫描规则过窄导致遗漏。

## Mitigations
- 以“明显乱码”作为硬性判断标准，保守修改。
- 通过清单复核确保可回溯。
