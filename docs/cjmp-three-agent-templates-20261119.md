## 4. KotlinFrameworkMapper任务

```text
对照本任务对应的固定Kotlin编译器/Analysis实现。
输出逐项映射：模块、包、文件、类/接口、方法/扩展/helper、
数据拥有关系、builder/resolve/consumer调用链和对应测试形状。
定位本项目已有抽象和共享根因，不自行编写生产实现。
如固定Kotlin没有同名/同职责入口，明确说明实际搜索范围与相关实现；
不能编造可照搬的API，不把IR与FIR的不同职责混称。
只向直属L1交付映射报告和需由Authority确认的语言差异。
```

CAPABILITY_ONLY模式时不执行上述源码任务，仅确认接收并结束。

## 5. CangjieSemanticsAuthority任务

```text
从固定官方仓颉源码确认该原条目的真实语法、类型、声明、诊断或CJO合同。
语法/语义需要文档补证时使用可用的仓颉docs MCP；证据不足如实说明，
不从当前项目实现反推正确语义，不把Kotlin特有语义带入仓颉。
必要cjc验证限定到正确用例，保留版本、命令、原诊断、源码/产物SHA。
明确区分正常语义完成与后端消费，保留原计划实际前端要求。
只写本分支证据/报告，不改生产或测试；结论仅返回直属L1。
```

## 7. KotlinParityGatekeeper任务

```text
只读审查本任务候选：[逐文件集合、实际SHA、映射与语义证据]。
按模块/包/文件/类/接口/方法/扩展/helper及真实调用流核对框架；
只允许有官方证据的仓颉语义差异和既定命名/模块映射。
确认正式消费者、类型/符号/owner身份、取消/失效/完成发布及正确测试合同。
拒绝没有Kotlin对应且无仓颉依据的兼容/兜底/退化层，
拒绝宽化nullable、空CFG、假phase、body=0及按fixture形状实现。
审查范围必须对应原要求及真实依赖；新增finding说明原ID、具体调用路径、
固定源码依据、受影响消费者和完整修复条件，不能另立全编译器目标。

输出ACCEPT/REJECT和完整边界，结论绑定本候选SHA。
局部接受必须列明仍OPEN要求；不将旧候选、编译成功或部分测试当完整接受。
只写获准的本分支报告，不改生产、测试或L0账，不派遣其他代理。
发现拒绝项直接返回直属L1，由其继续实现并重新派遣审查。
```

## 8. 阶段报告格式

L2只向L1返回角色报告；L1再汇总给L0。字段不能跨层直接转投：

```text
task_id / 原ID及子要求：
本层角色 / 所属分支 / 固定model_request：
阶段与实际完成产品：
变动文件或只读证据：
映射/官方语义/审查结论及SHA：
真实验证结果与证据路径：
尚未完成及真实阻断：
向直属父提出的下一步/资源请求：
```

L1另外报告本分支L2存活数量和名额释放状态。任何未执行的步骤明确写“未执行”，
不能用预期行为代替。L0只据L1汇总核对任务、依赖、验收与租约。
