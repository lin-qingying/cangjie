# 仓颉语言规范规约白皮书

本文面向本仓库的仓颉前端、CFIR、诊断、测试数据和 Analysis API 实现，用规约化方式整理仓颉语言的核心语法与语义。本文依据官方仓颉语言手册条目整理，不把本仓库当前实现行为当作语言真相源。

**维护基线：** 本文的语义来源为官方仓颉语言手册与官方编译器。改动语言规则或示例时，先复核官方章节；存在疑义时，使用最小程序经 `cjc` 验证。本文不替代官方规范，也不声明特定 `cjc` 发行版的永久行为。

## 1. 范围与真相源

### 1.1 规约范围

本文覆盖以下语言层面规则：

- 词法、标识符、关键字与源码组织。
- 包、模块、导入、可见性与顶层声明。
- 变量、属性、函数、Lambda、闭包与重载。
- 基础类型、表达式、控制流、操作符与赋值。
- `struct`、`class`、`interface`、`enum`、泛型、子类型、类型转换与模式匹配。
- 扩展、异常、并发与宏的语言边界。
- 面向编译器实现的建模和诊断约束。

本文不替代官方手册，也不覆盖标准库 API 的完整契约、后端 ABI、FFI 细节和宏系统内部实现 API。涉及这些内容时，仅记录会影响语言前端和诊断的边界规则。

### 1.2 术语级别

- “必须”表示语法或语义硬约束，违反时应诊断为错误。
- “不得”表示禁止行为，违反时应诊断为错误。
- “应”表示本仓库实现层面的建模要求，来自语言语义的直接约束。
- “可以”表示语言允许的合法形式。

### 1.3 基本设计原则

仓颉语言在前端实现中应按以下原则建模：

- 强类型：条件表达式必须是 `Bool` 或官方允许的 `let pattern` 条件组合，不能用数值是否为零模拟真假。
- 显式可变性：变量必须由 `let`、`var` 或 `const` 等修饰符明确表达初始化和赋值能力。
- 表达式化语义：`if`、`match`、`try` 等构造都有类型和值规则；赋值、复合赋值、自增自减和循环等副作用表达式通常产生 `Unit`。
- 声明与访问分离：变量是存储声明，属性是访问器声明，函数是可调用声明，三者不能用同一套语义兜底。
- 子类型不是隐式转换：子类型到父类型是子类型关系；不同类型之间没有一般隐式转换。

## 2. 词法与标识符

### 2.1 源文件

仓颉源码通常写在 `.cj` 文本文件中。源文件被编译为目标格式的二进制工件。前端应以 `.cj` 源文件作为普通源码输入单位。

### 2.2 标识符

普通标识符遵循 Unicode 15.0.0 的 `XID_Start` 与 `XID_Continue` 规则：

- 首字符必须属于 `XID_Start`，后续字符属于 `XID_Continue`。
- 也允许以下划线 `_` 开头，但后续必须至少存在一个 `XID_Continue` 字符。
- 标识符按 NFC 规范化处理。
- 普通标识符不得是关键字。

原始标识符使用反引号包裹普通标识符或关键字：

```cangjie
let `class` = 1
```

前端建模时应保留原始标识符的语法形态，同时在名称解析中使用其解包后的声明名。

### 2.3 关键字

关键字不能作为普通标识符使用。被反引号包裹后，关键字可作为原始标识符参与声明和引用。诊断应区分“关键字误用为普通标识符”和“合法原始标识符”。

## 3. 程序、包、模块与导入

### 3.1 顶层作用域

仓颉程序的顶层作用域可以声明：

- 全局变量。
- 全局函数。
- 自定义类型：`struct`、`class`、`enum`、`interface`。

非顶层作用域不能声明自定义类型，但可以声明局部变量和局部函数。类型定义体中的变量和函数分别是成员变量和成员函数。`enum` 和 `interface` 不支持成员变量；`prop` 是属性声明，不是成员变量，因此接口、枚举和扩展可通过 `prop` 声明访问器契约。

### 3.2 `main` 入口

可执行模块的入口是顶层 `main` 函数。`main` 的特殊规则：

- 定义时不需要 `func` 关键字。
- 可以没有参数，也可以声明 `Array<String>` 参数。
- 返回值类型可以是整数类型或 `Unit`。
- 一个可执行模块根中至多有一个入口 `main`。

### 3.3 包声明

包是最小编译单元，具有命名空间。一个包可以由多个源文件组成。包声明语法为：

```cangjie
package a.b
```

规约要求：

- `package` 声明必须是源文件中第一条非空、非注释语句。
- 包名必须与源文件路径匹配。
- 根源目录中未显式声明包时，属于默认包 `default`。
- 同一包内顶层声明不得重名，函数重载除外。

### 3.4 模块

模块是最小发布单元。访问级别中的 `protected` 以模块为边界。包依赖和导出规则必须以模块边界参与判断。

### 3.5 导入

导入语句必须位于包声明之后、其他声明之前。导入形式包括：

```cangjie
import fullPackageName.itemName
import packageName.*
import packageName.{foo, bar}
import {package1.foo, package2.bar}
import packageName.name as newName
import packageName as newPackageName
```

导入语义：

- 只能导入当前文件可见的顶层声明或包。
- 禁止导入当前源文件所在包的声明或定义。
- 禁止包之间形成循环导入依赖。
- 导入的成员作用域级别低于当前包声明的成员。
- 导入名与当前包声明重名时，当前包声明遮盖导入声明；若同名函数可构成重载，则按重载规则决议。
- `core` 包中的 `public` 声明会被隐式导入，因此 `String`、`Range` 等可直接使用。

### 3.6 重导出

`import` 可带访问修饰符：

- `private import`：默认，仅当前文件可见。
- `internal import`：当前包及子包可见。
- `protected import`：当前模块可见。
- `public import`：模块内外可见。

带 `public`、`protected` 或 `internal` 的导入可重导出导入成员。包本身不得被重导出。

### 3.7 顶层可见性

顶层访问修饰符语义如下：

| 修饰符 | 可见范围 |
|---|---|
| `private` | 当前文件 |
| `internal` | 当前包及子包 |
| `protected` | 当前模块 |
| `public` | 所有包 |

默认规则：

- `package` 支持 `internal`、`protected`、`public`，默认 `public`。
- `import` 支持全部访问修饰符，默认 `private`。
- 其他顶层声明支持全部访问修饰符，默认 `internal`。

访问级别排序为 `public > protected > internal > private`。一个声明的可见性不得高于其签名中使用类型的可见性；函数体和初始化表达式内部可以使用本包可见的声明，不构成签名泄露。

## 4. 声明体系总览

### 4.1 顶层声明类别

顶层声明包括：

- 包声明：`package`。
- 导入声明：`import`。
- 变量声明：`let`、`var`、`const`。
- 函数声明：`func` 以及特殊入口 `main`。
- 类型声明：`struct`、`class`、`enum`、`interface`。
- 扩展声明：`extend`。
- 宏包和宏声明：`macro package` 及宏相关声明。

### 4.2 声明名与作用域

大括号包围的语法结构形成作用域。仓颉不允许脱离语法结构单独使用 `{}` 创建块作用域。

作用域规则：

- 当前作用域声明在当前作用域和内层作用域有效。
- 内层作用域声明在外层作用域无效。
- 内层声明可以遮盖外层同名声明。
- 同一作用域中变量和函数不得共享同一名字；函数声明之间可按签名构成重载。

## 5. 变量规约

### 5.1 变量声明语法

变量声明的一般形式为：

```text
修饰符 变量名: 变量类型 = 初始值
```

常用修饰符：

- `let`：不可变变量。
- `var`：可变变量。
- `const`：编译期求值且运行时不可变的常量变量。
- `private`、`internal`、`protected`、`public`：可见性。
- `static`：静态成员变量。

仓颉变量声明必须有可变性或常量修饰语义，不能把未带 `let`、`var`、`const` 的声明当成普通变量。

### 5.2 `let`

`let` 声明不可变变量。规约要求：

- `let` 变量最多被赋值一次。
- 声明时未初始化的局部 `let` 或实例成员 `let`，必须在首次读取前完成初始化。
- 编译器无法证明初始化唯一性时，应保守报错。
- `let` 引用类型变量限制的是引用关系不可改变，不表示引用对象内部状态一定不可变。

### 5.3 `var`

`var` 声明可变变量。规约要求：

- `var` 变量初始化后可以多次赋值。
- 赋值表达式右侧类型必须与变量类型一致，或满足相应子类型关系。
- 对值类型变量赋值通常覆盖其独占值；对引用类型变量赋值改变引用关系。

### 5.4 `const`

`const` 是特殊变量修饰符。规约要求：

- `const` 变量必须在声明时初始化。
- 初始化表达式在编译时求值。
- 初始化后运行时不可改变。
- `const` 可用于全局变量、局部变量、静态成员变量。
- `const` 变量不能在扩展中定义。
- `const` 具有深度不可变语义，其成员不能作为左值。

`const` 比 `let` 更严格。`let` 只约束变量赋值次数；`const` 同时要求编译期求值和深度不可变。

### 5.5 初始化规则

初始化要求：

- 全局变量必须在声明处初始化。
- 静态成员变量必须在声明处初始化。
- 局部变量和实例成员变量可以省略初始值，但必须带类型标注，并在引用前初始化。
- 若变量声明同时给出类型和初值，初值类型必须符合变量类型。
- 若初值类型明确，可以省略类型标注，由编译器推断。

### 5.6 值类型与引用类型

语言层面区分值类型变量和引用类型变量：

- `class` 和 `Array` 属于引用类型。
- 基础数据类型和 `struct` 属于值类型。

赋值语义：

- 值类型变量赋值通常产生副本，修改副本不影响原值。
- 引用类型变量赋值建立引用关系，多个变量可共享同一对象。
- `let` 引用类型变量不能被重新绑定，但其引用对象的可变成员仍可能被修改。

## 6. `prop` 与 `var/let` 的规范差异

### 6.1 结论

`prop` 不是变量。`var` 和 `let` 声明存储位置，`prop` 声明访问器。仓颉源码中 `x.p` 的读写语法看起来像成员变量访问，但属性语义必须按 getter 和 setter 调用建模。

### 6.2 属性声明语法

属性可以定义在：

- `interface`
- `class`
- `struct`
- `enum`
- `extend`

典型语法：

```cangjie
class Foo {
    public prop a: Int64 {
        get() { 0 }
    }

    public mut prop b: Int64 {
        get() { 0 }
        set(v) {}
    }
}
```

无 `mut` 的 `prop`：

- 必须且只能定义 getter。
- 读属性时调用 getter。
- 不能被赋值。
- 行为类似 `let` 的只读访问效果，但不是 `let` 变量。

带 `mut` 的 `prop`：

- 必须定义 getter 和 setter。
- 读属性时调用 getter。
- 给属性赋值时调用 setter。
- 行为类似 `var` 的可读写访问效果，但不是 `var` 变量。

### 6.3 getter 和 setter 类型

设属性类型为 `T`：

- getter 函数类型是 `() -> T`。
- setter 函数类型是 `(T) -> Unit`。

属性表达式求值规则：

```cangjie
let y = obj.p
```

等价语义是执行 `p` 的 getter 并使用其返回值。

属性赋值规则：

```cangjie
obj.p = value
```

等价语义是执行 `p` 的 setter，并把 `value` 作为 setter 参数传入。整个赋值表达式类型仍为 `Unit`。

### 6.4 `prop` 与变量的差异表

| 维度 | `let` / `var` 变量 | `prop` 属性 |
|---|---|---|
| 本质 | 具名存储位置 | getter/setter 访问器 |
| 声明关键字 | `let`、`var`、`const` | `prop`、`mut prop` |
| 是否隐含存储 | 是 | 否 |
| 读取语义 | 读取变量当前值 | 调用 getter |
| 写入语义 | 写入变量存储位置，受 `let`/`var` 约束 | 调用 setter，仅 `mut prop` 可写 |
| 接口中声明 | 不允许成员变量 | 允许抽象属性 |
| 扩展中声明 | 扩展不能增加成员变量 | 扩展可以增加属性 |
| 覆盖/重定义 | 成员变量不是属性覆盖语义 | 属性支持 `open`、`override`、`redef` |
| 抽象契约 | 变量不能作为接口抽象契约 | 属性可以作为接口或抽象类契约 |
| 递归风险 | 读写变量自身不是函数调用 | getter/setter 内访问属性自身会递归调用 |

### 6.5 典型封装模型

属性常用于封装私有变量：

```cangjie
class Counter {
    private var backing: Int64 = 0

    public mut prop value: Int64 {
        get() { backing }
        set(v) { backing = v }
    }
}
```

这里 `backing` 是成员变量，`value` 是属性。外部访问 `value` 不拥有 `backing` 的存储位置，只触发访问器逻辑。

### 6.6 抽象属性与覆盖

`interface` 和抽象类可以声明无实现属性：

```cangjie
interface Sized {
    prop size: Int64
    mut prop capacity: Int64
}
```

实现要求：

- 实现类型必须提供属性实现。
- 父属性为 `mut prop` 时，子属性也必须是 `mut prop`。
- 覆盖属性必须保持相同属性类型。
- 成员属性支持 `open`、`override`、`redef`。

### 6.7 限制

对于数值、元组、函数、`Bool`、`Unit`、`Nothing`、`String`、`Range` 和 `enum` 类型，在其扩展和声明中不能声明 `mut prop`，也不能实现包含 `mut prop` 的接口。

### 6.8 编译器实现要求

前端和 CFIR 不得把 `prop` 降级成字段：

- PSI/AST 应区分属性声明、变量声明和函数声明。
- 符号层应区分 property symbol、variable symbol 和 function symbol。
- 解析属性读访问时应产生 getter 调用语义。
- 解析属性赋值时应检查 `mut`、setter 存在性和 setter 参数类型。
- 接口属性应作为成员契约参与实现检查。
- 扩展属性应按扩展成员规则参与可见性、导入导出和冲突检查。
- getter/setter 中访问属性自身应按普通函数递归调用处理，不得误判为 backing field 访问。

## 7. 基础类型与内建类型

### 7.1 整数

整数类型包括：

- 有符号：`Int8`、`Int16`、`Int32`、`Int64`、`IntNative`。
- 无符号：`UInt8`、`UInt16`、`UInt32`、`UInt64`、`UIntNative`。

无上下文的整数字面量默认类型为 `Int64`。整数后缀用于指定类型，例如 `i8`、`u8` 等。字节字面量 `b'x'` 的类型是 `UInt8`。

整数算术必须按目标类型检查溢出；语言手册说明算术结果会被检测并禁止值溢出。溢出策略还可受相关属性宏影响。

### 7.2 浮点数

浮点类型包括 `Float16`、`Float32`、`Float64`，分别对应 IEEE binary16、binary32、binary64。浮点字面量支持 `f16`、`f32`、`f64` 后缀。浮点类型不支持 `++` 和 `--`。

### 7.3 `Bool`

`Bool` 只有 `true` 和 `false`。条件表达式必须是 `Bool` 或官方允许的模式条件组合，不能用整数、浮点数或引用值作为条件。

### 7.4 `Rune`

`Rune` 表示 Unicode 字符。字符字面量使用 `r` 前缀，可用单引号或双引号形式。`Rune` 可按 Unicode 值比较。`Rune` 与 `UInt32` 之间通过显式构造转换。

### 7.5 `String`

`String` 表示 Unicode 字符序列。支持单行字符串、多行字符串、原始多行字符串和插值：

```cangjie
let name = "Cangjie"
let text = "hello ${name}"
```

插值表达式中最后一项的值替换该插值位置。`String` 支持 `+` 拼接和比较操作。

### 7.6 `Unit`

`Unit` 表示只关注副作用的表达式类型，唯一值为 `()`。典型 `Unit` 表达式包括：

- 赋值。
- 复合赋值。
- `++` 和 `--`。
- 循环表达式。
- 值未被使用的多分支表达式。
- 无返回值函数调用。

### 7.7 `Nothing`

`Nothing` 没有任何值，是所有类型的子类型。以下表达式类型为 `Nothing`：

- `break`
- `continue`
- `return`
- `throw`

程序执行到这些表达式后，后续同一路径代码不可达。当前官方规则中，显式在类型位置使用 `Nothing` 受到限制，前端不得把它当作普通可实例化类型。

### 7.8 元组

元组类型语法：

```cangjie
(T1, T2, ..., TN)
```

规约要求：

- 元组至少二元。
- 元组长度固定。
- 元组元素不可被单独更新。
- 若绑定元组的变量是 `var`，可以整体重新赋值。
- 元组元素只能用整数字面量索引。
- 元组类型参数名可选，但必须全有或全无，且不作为字段访问名。

### 7.9 数组

`Array<T>` 是数组类型：

```cangjie
let xs = [1, 2, 3]
```

规约要求：

- 数组长度固定。
- 数组元素可变。
- `size` 返回长度。
- 下标索引类型必须是 `Int64`。
- 支持范围切片。
- `Array` 在语言使用上属于引用类型，赋值会共享元素存储。

`VArray<T, $N>` 是固定字面量大小的值数组。

### 7.10 区间

`Range<T>` 表示区间，包含 `start`、`end`、`step`。`T` 需要支持比较以及与 `Int64` 的加法。`step` 类型是 `Int64`，不得为零。

区间操作符：

- `a..b`：左闭右开。
- `a..=b`：左闭右闭。

## 8. 表达式与操作符

### 8.1 代码块

函数体、分支体、循环体等由一组声明和表达式组成。代码块类型通常由最后一项决定：

- 最后一项是表达式时，代码块类型是该表达式类型。
- 最后一项是声明或代码块为空时，代码块类型是 `Unit`。

### 8.2 赋值表达式

赋值表达式类型为 `Unit`，值为 `()`。因此链式赋值不成立，不能依赖赋值表达式结果作为被赋值值。

规约要求：

- 右侧表达式先求值。
- 随后求左侧目标。
- 最后执行赋值。
- `let` 左值在已初始化后不得再次赋值。
- 属性赋值必须解析为 setter 调用。

### 8.3 复合赋值与自增自减

复合赋值表达式类型为 `Unit`。`++` 与 `--` 仅支持后缀形式，表达式类型为 `Unit`。

### 8.4 算术操作符

常见算术操作符包括 `+`、`-`、`*`、`/`、`%`、`**`。规约要求：

- 一般算术操作数必须类型一致。
- `%` 仅适用于整数类型。
- `**` 的官方规则包括：`Int64` 底数与 `UInt64` 指数返回 `Int64`；`Float64` 底数与 `Int64` 或 `Float64` 指数返回 `Float64`。

### 8.5 逻辑操作符

`&&` 和 `||` 具有短路语义：

- `a && b` 中，若 `a` 为 `false`，不得求值 `b`。
- `a || b` 中，若 `a` 为 `true`，不得求值 `b`。

逻辑操作数应为 `Bool`。

### 8.6 多重赋值

多重赋值使用元组形态的左右两侧。`_` 可用于忽略对应位置的结果，但该位置仍需参与类型检查。

### 8.7 `if` 表达式

语法：

```cangjie
if (condition) {
    branch1
} else {
    branch2
}
```

条件可以是：

- `Bool` 表达式。
- `let pattern` 条件。
- 多个 `let pattern` 与 `Bool` 表达式通过逻辑与或逻辑或连接形成的表达式。

执行语义：

- 条件为 `true` 执行 `if` 分支。
- 条件为 `false` 执行 `else` 分支。
- `else` 可省略。

类型规则：

- 有 `else` 且表达式值被使用时，若上下文期望类型为 `T`，各分支代码块类型必须是 `T` 的子类型，整体类型为 `T`。
- 有 `else` 且无上下文期望类型时，整体类型为各分支代码块类型的最小公共父类型；不存在则报错。
- 有 `else` 但值未被使用时，整体类型为 `Unit`，分支不按上述共同类型规则检查。
- 无 `else` 时，整体类型为 `Unit`，值为 `()`。

### 8.8 `while`

语法：

```cangjie
while (condition) {
    body
}
```

`condition` 与 `if` 条件规则一致。执行语义为先判断条件，再执行循环体。条件为 `false` 时结束循环。

### 8.9 `do-while`

语法：

```cangjie
do {
    body
} while (condition)
```

执行语义为先执行一次循环体，再判断 `Bool` 条件。

### 8.10 `for-in`

`for-in` 用于遍历扩展了 `Iterable<T>` 的类型实例：

```cangjie
for (item in items) {
    body
}
```

规约要求：

- 迭代变量可以是单个标识符，也可以是多个标识符构成的元组。
- 迭代变量绑定每轮迭代器当前指向的数据，可作为循环体局部变量使用。
- 序列表达式只求值一次，遍历针对该表达式的值进行。
- 序列表达式类型必须扩展 `Iterable<T>`。
- 执行时先计算序列表达式并初始化迭代器，再循环更新迭代器、绑定迭代变量并执行循环体，直到迭代器终止。
- 内置区间和数组等类型已经扩展 `Iterable<T>`。
- 循环整体用于副作用场景时类型为 `Unit`。

### 8.11 `break` 与 `continue`

`break` 和 `continue` 只能出现在循环体中。

- `break` 终止当前循环，继续执行循环后代码。
- `continue` 结束本轮循环，进入下一轮。
- 二者类型都是 `Nothing`。

### 8.12 `try`

`try` 是表达式，详见异常章节。普通 `try` 的类型与 `if`、`match` 类似，由 `try` 块和 `catch` 块的类型决定，`finally` 不参与最小公共父类型计算。若 `try` 表达式值未被使用，类型为 `Unit`。

## 9. 函数、Lambda、闭包与重载

### 9.1 函数定义

函数语法：

```cangjie
func name(params): ReturnType {
    body
}
```

返回类型可省略，由函数体和 `return` 表达式推断。若显式声明返回类型：

- 函数体类型必须是返回类型的子类型。
- 所有 `return e` 的 `e` 必须是返回类型的子类型。
- `return` 等价于 `return ()`，适用于 `Unit` 返回语义。
- `return` 表达式本身类型为 `Nothing`。

### 9.2 参数

普通参数：

```cangjie
p: T
```

命名参数：

```cangjie
p!: T
```

默认值仅允许命名参数：

```cangjie
p!: T = expr
```

参数规则：

- 非命名参数必须位于命名参数之前。
- 函数参数在函数体内不可变。
- 实参类型必须是对应形参类型的子类型。
- 多个命名实参可乱序传递。
- 省略带默认值的命名实参时使用默认值。

### 9.3 函数类型

函数类型语法：

```cangjie
(T1, T2) -> R
```

函数类型右结合：

```cangjie
T1 -> T2 -> R
```

应解析为：

```cangjie
T1 -> (T2 -> R)
```

函数名可作为函数类型表达式。重载函数名在缺少上下文函数类型时可能无法决议。

### 9.4 Lambda

Lambda 语法：

```cangjie
{ p1: T1, p2: T2 => body }
```

规则：

- `=>` 前为参数列表，可以为空。
- 参数类型可由上下文推断。
- 返回类型由上下文或函数体推断。
- Lambda 可立即调用。
- 作为尾随 Lambda 时，语法可按官方规则省略部分形式。

### 9.5 闭包捕获

Lambda 和局部函数可以捕获静态作用域内的局部变量。捕获规则：

- 被捕获变量必须在闭包定义处可见。
- 被捕获变量必须在闭包定义前已初始化。
- 捕获 `var` 变量会带来逃逸限制：此类闭包或函数可直接调用，但不能赋值给变量、返回、作为普通表达式或实参传递。
- 捕获限制具有传递性。

### 9.6 函数重载

重载只适用于函数声明和构造函数，不适用于函数类型变量。变量和函数不得在同一作用域共享同一名称。

重载决议原则：

- 优先考虑更高作用域级别的候选。
- 同一作用域级别内选择最具体候选。
- 无唯一最具体候选时应诊断歧义。

## 10. 复合类型与面向对象

### 10.1 `struct`

`struct` 是值类型，只能在顶层定义。语法：

```cangjie
struct Name {
    members
}
```

定义体可包含：

- 成员变量。
- 成员属性。
- 静态初始化器。
- 构造函数。
- 成员函数。

规约要求：

- `struct` 不能递归定义自身存储。
- `struct` 实例函数默认不能修改实例自身。
- 需要修改实例自身的函数必须标记为 `mut func`。
- `let` 绑定的 `struct` 实例不能调用 `mut` 函数。
- `mut func` 仅用于 `interface`、`struct` 和 `struct` 扩展。
- `mut func` 中 `this` 具有特殊语义，不能被捕获或当作普通表达式使用。
- `mut func` 内的 Lambda 或局部函数不能捕获实例成员。

### 10.2 `class`

`class` 是引用类型，只能在顶层定义。语法：

```cangjie
class Name <: Parent & Interface1 & Interface2 {
    members
}
```

定义体可包含：

- 成员变量。
- 成员属性。
- 静态初始化器。
- 构造函数。
- 成员函数。
- 操作符函数。

继承规则：

- `class` 支持继承，`struct` 不支持继承。
- 默认类不可被继承。
- 非抽象类必须标记 `open` 才能被继承。
- 类仅支持单继承。
- 未显式声明直接父类时，直接父类为 `Object`。
- `Object` 没有成员。
- 抽象类总是可被继承。
- `sealed abstract` 类只能在同一包内被继承。

### 10.3 `This` 类型

`This` 类型只能用于类的实例成员函数返回类型，表示当前类，并在子类接收者上解析为子类类型。

### 10.4 `interface`

`interface` 是抽象类型，用于定义行为，不承载数据存储。语法：

```cangjie
interface Name {
    func f(): Unit
    prop p: Int64
}
```

接口成员包括：

- 成员函数。
- 操作符重载函数。
- 成员属性。
- 静态成员。

规则：

- 接口默认开放。
- 接口成员默认并强制为 `public`，实现成员也必须是 `public`。
- 接口可 `sealed`，被密封后只能在同一包内继承、实现或扩展实现。
- 接口可继承多个接口。
- 实现类型必须实现所有抽象成员。
- 接口成员函数返回类型通常要求匹配；当接口返回类型是类类型时，实现可返回其子类型。
- 多个默认实现冲突时，实现类型必须自行实现。
- `Any` 是内置接口，所有接口继承 `Any`，所有非接口类型实现 `Any`。

### 10.5 `enum`

`enum` 是代数数据类型风格的枚举，只能在顶层定义。语法：

```cangjie
enum Option<T> {
    Some(T) | None
}
```

规则：

- 定义体列出构造器，构造器之间用 `|` 分隔。
- 第一个 `|` 可省略。
- 至少存在一个具名构造器。
- 构造器可以无参数，也可以带参数。
- 同名构造器在参数个数不同时可共存。
- 最后可出现一个 `...` 非穷尽构造器，且最多一个。
- `enum` 支持递归定义。
- `enum` 可定义成员函数、静态函数、操作符函数、成员属性。
- 构造器、成员函数和属性不得同名。

构造枚举值可使用：

```cangjie
Option<Int64>.Some(1)
Some(1)
```

当构造器名与类型、变量、函数或类冲突时，非限定名解析到普通定义，应使用 `EnumType.Constructor`。

### 10.6 `Option`

`Option<T>` 是标准枚举：

```cangjie
Option<T> = Some(T) | None
```

`?Ty` 等价于 `Option<Ty>`。在 `Option<T>` 上下文中，`T` 值可被包装成 `Some`，这不是一般隐式类型转换。

## 11. 泛型、子类型与类型转换

### 11.1 泛型

用户自定义泛型类型可带类型形参和 `where` 约束。泛型声明签名中的约束可见性不得高于约束类型自身可见性。

泛型用户自定义类型构造器默认不变：

- 即使 `D <: C`，也不能推出 `I<D> <: I<C>`。
- 元组和函数类型使用其内建方差规则，不适用普通用户自定义泛型不变性。

### 11.2 子类型

子类型关系记为 `<:`。基本规则：

- `T <: T`。
- `Nothing <: T`。
- `T <: Any`。
- 任意类类型 `<: Object`。
- 类继承产生子类型关系。
- 接口继承和实现产生子类型关系。
- 扩展实现接口产生子类型关系。
- 子类型关系具有传递性。

元组类型按元素协变：

```text
(S1, S2) <: (T1, T2) 当且仅当 S1 <: T1 且 S2 <: T2
```

函数类型参数逆变、返回协变：

```text
(U1) -> S2 <: (U2) -> S1 当且仅当 U2 <: U1 且 S2 <: S1
```

### 11.3 类型转换

仓颉不同类型之间没有一般隐式转换。规约要求：

- 子类型赋给父类型是子类型规则，不是隐式转换。
- 数值转换使用目标类型构造语法，例如 `Int32(x)`。
- 数值转换溢出可导致编译期错误或运行时异常。
- `Rune` 到 `UInt32` 使用 `UInt32(e)`。
- 整数到 `Rune` 使用 `Rune(num)`，仅当数值是合法 Unicode scalar value。

### 11.4 运行时类型检查

`is` 用于运行时类型检查。`as` 返回 `Option<T>`：

- 转换成功返回 `Some(value)`。
- 转换失败返回 `None`。

前端不得把 `as` 直接建模为必然成功的强制转换。

## 12. 模式匹配

### 12.1 `match` 形态

带匹配值：

```cangjie
match (expr) {
    case pattern where condition => body
    case _ => body
}
```

不带匹配值：

```cangjie
match {
    case condition => body
    case _ => body
}
```

### 12.2 执行语义

- `case` 按顺序检查。
- 第一个匹配成功的分支被执行。
- 执行某一分支后退出整个 `match`。
- `where` 守卫必须是 `Bool`。
- 多个同类模式可用 `|` 连接。

### 12.3 穷尽性

`match` 必须穷尽。若编译器不能证明穷尽，应报错。对于非穷尽枚举，必须使用 `_` 或绑定模式覆盖剩余情况。

### 12.4 类型规则

- 有上下文期望类型 `T` 时，每个分支代码块类型必须是 `T` 的子类型，整体类型为 `T`。
- 无上下文期望类型时，整体类型为各分支类型的最小公共父类型。
- 值未被使用时，整体类型为 `Unit`。

### 12.5 模式类别

支持的核心模式包括：

- 常量模式。
- 通配符模式 `_`。
- 绑定模式 `id`。
- 元组模式。
- 类型模式 `_: T` 或 `id: T`。
- 枚举模式。
- 上述模式的嵌套组合。

绑定模式引入不可变变量。同一模式中不得重复绑定同名变量。`|` 连接的模式不得引入变量。

### 12.6 可反驳性

- 常量模式和类型模式可反驳。
- 通配符模式和绑定模式不可反驳。
- 元组模式在所有元素模式不可反驳时不可反驳。
- 枚举模式仅当枚举只有一个带参数构造器且嵌套模式不可反驳时不可反驳。

## 13. 扩展

### 13.1 扩展能力

扩展使用 `extend` 声明：

```cangjie
extend String {
    public func printSize() {
        println("${this.size}")
    }
}
```

扩展可以为当前包可见的类型添加功能，但不能扩展函数、元组和接口类型。

扩展可添加：

- 成员函数。
- 操作符重载函数。
- 成员属性。
- 接口实现。

扩展不得：

- 增加成员变量。
- 声明无实现的函数或属性。
- 在扩展函数或属性上使用 `open`、`override`、`redef`。
- 访问被扩展类型的 `private` 成员。
- 遮盖被扩展类型已有成员。
- 遮盖其他扩展已经增加的成员。

### 13.2 直接扩展

直接扩展不实现额外接口：

```cangjie
extend String {
    public func f(): Unit {}
}
```

泛型类型可按完全实例化类型扩展，也可引入扩展泛型形参：

```cangjie
extend Foo<Int64> {}
extend<T> MyList<T> {}
extend<T1, T2> Pair<T1, T2> where T1 <: Eq<T1>, T2 <: Eq<T2> {}
```

扩展泛型形参必须直接或间接用于被扩展类型。

### 13.3 接口扩展

接口扩展为现有类型实现接口：

```cangjie
extend<T> Array<T> <: PrintSizeable {
    public func printSize() {}
}
```

语义上相当于被扩展类型实现该接口。多个接口用 `&` 分隔：

```cangjie
extend Foo <: I1 & I2 & I3 {}
```

若被扩展类型已包含接口要求的函数或属性，扩展中不需要且不得重新实现这些成员。

### 13.4 扩展修饰符和访问

扩展声明本身不能带访问修饰符。扩展成员可使用：

- `static`
- `public`
- `protected`
- `internal`
- `private`
- `mut`

扩展实例成员可使用 `this`，但不能使用 `super`。

### 13.5 孤儿规则

仓颉禁止孤儿接口扩展。为其他包类型实现另一个包接口时，接口扩展必须定义在被扩展类型所在包或接口所在包中。

### 13.6 扩展导入导出

扩展可被导入和导出，但不通过显式导入扩展名完成。访问某扩展成员需要导入：

- 被扩展类型。
- 接口扩展中的接口。
- 泛型约束中影响可见性的类型。

接口扩展导出的成员仅限于接口包含的成员。

## 14. 异常

### 14.1 异常类型体系

仓颉异常类包括 `Error` 和 `Exception`：

- `Error` 描述运行时系统内部错误和资源耗尽错误。应用程序不应抛出此类错误，出现后应尽量安全终止。
- `Exception` 描述程序运行时逻辑错误或 IO 错误，需要在程序中捕获处理。

开发者不能继承内置 `Error` 或其子类来自定义异常，可以继承 `Exception` 或其子类。

### 14.2 `throw`

语法：

```cangjie
throw Exception("message")
```

规约要求：

- `throw` 后表达式必须是 `Exception` 的子类型。
- `Error` 不允许被手动 `throw`。
- `throw` 表达式类型为 `Nothing`。
- 未被捕获的异常由系统默认异常处理函数处理。

### 14.3 普通 `try`

普通 `try` 包含 `try` 块、零个或多个 `catch` 块和可选 `finally` 块：

```cangjie
try {
    body
} catch (e: SomeException) {
    handle
} finally {
    cleanup
}
```

规则：

- `try` 块可抛出异常，并由后续 `catch` 捕获。
- 没有 `catch` 时必须有 `finally`。
- `catch` 按顺序匹配，匹配成功后忽略后续 `catch`。
- 若某个 `catch` 捕获范围完全被前序 `catch` 覆盖，应产生不可达 warning。
- `finally` 无论异常是否发生都会执行。
- 若异常未处理，执行完 `finally` 后继续向外抛出。
- `try` 块和各 `catch` 块作用域互相独立。

类型规则：

- 普通 `try` 可出现在任何允许表达式的位置。
- 整体类型由 `try` 块和 `catch` 块的类型求最小公共父类型。
- `finally` 块不参与最小公共父类型计算。
- 若 `try` 表达式值未使用，整体类型为 `Unit`。

### 14.4 `try-with-resources`

语法：

```cangjie
try (r = ResourceImpl()) {
    body
}
```

规则：

- `ResourceSpecification` 可有一个或多个，使用逗号分隔。
- `catch` 和 `finally` 可选。
- 资源对象类型必须实现 `Resource` 接口。
- 离开作用域时按 `isClosed()` 与 `close()` 约定自动释放资源。
- `ResourceSpecification` 不影响整个 `try` 表达式类型。
- `try-with-resources` 表达式类型为 `Unit`。

### 14.5 `catchPattern`

类型模式：

```cangjie
catch (e: ExceptionClass) {}
catch (e: ExceptionClass1 | ExceptionClass2) {}
```

语义：

- `Identifier: ExceptionClass` 捕获该异常类及其子类，并绑定为该类型。
- `Identifier: A | B` 捕获任一类型及其子类，绑定变量类型为这些类型的最小公共父类型。
- `_` 捕获任意 `Exception` 子类异常，不引入绑定。

## 15. 并发与线程边界

### 15.1 `spawn`

`spawn` 表达式创建新线程并返回 `Future<T>`，其中 `T` 与传入 Lambda 的返回类型一致：

```cangjie
let fut: Future<Unit> = spawn { =>
    work()
}
```

### 15.2 `Future<T>`

`Future<T>` 提供等待与取值能力：

- `get(): T` 阻塞等待线程结束并返回结果，线程中异常会由该调用抛出。
- `get(timeout: Duration): T` 等待指定时间，超时抛出 `TimeoutException`；`timeout <= Duration.Zero` 时行为同 `get()`。
- `tryGet(): Option<T>` 非阻塞尝试取值，未完成返回 `None`，完成返回 `Some(result)`。

并发调度顺序不确定。只有显式同步，如调用 `get()`，才能建立相应顺序保证。

### 15.3 `Thread`

线程通过 `Thread` 对象表示。`Thread` 不能直接实例化，可通过 `Future<T>.thread` 或 `Thread.currentThread` 获取。`Thread` 暴露如 `id`、`hasPendingCancellation` 等属性。

## 16. 宏与注解边界

### 16.1 宏包

宏定义需要放在 `macro package` 声明的包中。被 `macro package` 限定的包仅允许宏定义对外可见，其他声明为包内可见。

当前编译器约束：

- 宏定义与宏调用不允许在同一包中。
- 宏包必须先编译，再编译宏调用包。
- 宏调用包中不允许出现宏定义。
- 宏定义需要 `public` 修饰以导出给其他包使用。

### 16.2 宏分类

仓颉宏可分为：

- 非属性宏：只接受被转换代码，不接受属性参数。
- 属性宏：通过注解式语法影响被标记声明或代码。

前端规约中，宏展开前后的节点都应保留足够位置信息，以支持诊断映射、测试数据和 IDE 分析。

## 17. 操作符重载

自定义类型可通过定义操作符函数支持操作符重载。操作符函数与普通函数相似，但函数名是对应操作符。规约要求：

- 只有语言允许重载的操作符才能定义操作符函数。
- 操作符函数应参与普通成员解析、可见性检查和重载决议。
- 对内建类型已有的操作符语义不得被普通扩展规则破坏。

## 18. 面向实现的前端规约

### 18.1 PSI/AST

PSI/AST 必须保留以下语义差异：

- `let`、`var`、`const` 变量声明。
- 成员变量与顶层变量、局部变量。
- `prop`、`mut prop`、getter、setter。
- 函数声明、局部函数、构造函数、操作符函数。
- `class`、`struct`、`enum`、`interface`、`extend`。
- `match` 模式与普通表达式。
- `try`、`catchPattern`、`try-with-resources`。
- 原始标识符和普通标识符。

### 18.2 名称解析

名称解析必须按作用域级别、导入优先级和重载规则执行：

- 当前包声明优先于导入声明。
- 内层作用域遮盖外层作用域。
- 函数重载只在函数声明和构造函数之间成立。
- 非函数声明重名不得被重载规则吞掉。
- 枚举构造器非限定访问存在冲突时，应优先普通定义，需要限定名访问构造器。

### 18.3 类型系统

类型系统实现必须区分：

- 子类型关系与显式转换。
- `Nothing` 的底类型语义与其类型位置限制。
- `Unit` 的副作用表达式语义。
- 元组和函数类型的内建方差。
- 用户自定义泛型类型构造器的不变性。
- `Option<T>` 上下文包装与一般隐式转换。

### 18.4 控制流与初始化分析

控制流分析必须处理：

- `let` 变量单次赋值。
- 局部变量和实例成员变量引用前初始化。
- 全局变量和静态成员变量声明处初始化。
- `return`、`break`、`continue`、`throw` 的 `Nothing` 控制流中断。
- `try-catch` 初始化的保守规则。
- `if`、`match`、`try` 的表达式类型和未使用值时的 `Unit` 规则。

### 18.5 成员与扩展

成员检查必须处理：

- `struct` 值语义和 `mut func` 限制。
- `class` 继承、开放性、抽象性和密封性。
- `interface` 默认实现冲突。
- `prop` 抽象契约与 `mut` 保持规则。
- 扩展不得增加成员变量。
- 扩展不得遮盖原类型成员或其他扩展成员。
- 接口扩展引入的子类型关系。
- 孤儿接口扩展禁止规则。

### 18.6 诊断要求

诊断应优先使用结构化语言错误，不应通过通用异常兜底。至少应覆盖：

- 非 `Bool` 条件。
- 未初始化读取。
- 重复初始化 `let`。
- 给不可变变量或只读属性赋值。
- 缺失属性 getter/setter。
- `mut prop` 实现不匹配。
- 接口/抽象属性未实现。
- 不合法顶层或局部声明位置。
- 导入不可见声明、自导入和循环导入。
- 可见性泄露。
- 函数重载歧义。
- `match` 不穷尽。
- 非法类型转换。
- 扩展遮盖、孤儿扩展和非法扩展成员。
- 非法 `throw` 类型。
- `catch` 不可达 warning。

## 19. 术语对照

| 术语 | 规约含义 |
|---|---|
| 变量 | `let`、`var`、`const` 声明的具名存储 |
| 属性 | `prop` 声明的 getter/setter 访问器 |
| `mut prop` | 同时具备 getter 和 setter 的可写属性 |
| 值类型 | 赋值通常复制数据的类型，如基础类型和 `struct` |
| 引用类型 | 赋值共享对象引用的类型，如 `class` 和 `Array` |
| 子类型 | `<:` 关系，可用于赋值、传参和返回类型检查 |
| 显式转换 | `T(e)`、`Rune(num)`、`UInt32(rune)`、`as` 等显式语法 |
| `Unit` | 副作用表达式的类型，唯一值 `()` |
| `Nothing` | 无值底类型，表示控制流不继续 |
| 直接扩展 | 不实现接口的 `extend` |
| 接口扩展 | 通过 `extend T <: I` 为类型实现接口 |
