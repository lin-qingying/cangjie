# 准备工具链

## 目标

这一课只做三件事：确认命令行能找到仓颉工具链，建立教程用的工作目录，知道出现“命令找不到”时先查哪里。完成后你应该能在终端里运行 `cjc` 和 `cjpm`。

## 检查命令

打开一个新的终端，先执行：

```bash
cjc -v
cjpm -h
```

如果 `cjc` 能输出版本信息，编译器已经在当前终端可用。如果 `cjpm -h` 能输出帮助文本，包管理器也已经可用。后面的前几课可以只用 `cjc`，到包拆分章节再使用 `cjpm`。

## 建立练习目录

在任意不会和仓库源码混在一起的位置创建目录。下面命令只是示例，路径可以换成你自己的：

```bash
mkdir taskbook
cd taskbook
```

后续章节默认你在这个目录中写文件。第一阶段只有一个文件：

- `main.cj`：入口程序。

第二阶段会增加模型文件：

- `model/task.cj`：任务和状态。
- `store/memory.cj`：内存中的任务仓库。

第三阶段再加入包与模块结构。

## 环境变量排查

如果终端提示找不到 `cjc`，通常是当前终端没有加载工具链环境。按这个顺序查：

1. 工具链安装目录是否存在。
2. 安装目录下的 `bin` 是否加入 `PATH`。
3. 当前终端是否重新打开过。
4. 安装包提供的环境脚本是否只对当前 shell 生效。

不要在教程目录里复制编译器可执行文件。正确做法是让 shell 能从 `PATH` 找到工具链。

## 编译器和包管理器的分工

`cjc` 直接编译 `.cj` 源文件，适合单文件或简单实验：

```bash
cjc main.cj -o taskbook
```

`cjpm` 负责项目级构建、依赖和模块组织。教程前半段先用 `cjc` 让语法反馈更直接，后半段再切到 `cjpm`，这样你能看清“语言规则”和“工程组织”之间的边界。

## 检查点

确认下面三项都成立：

- `cjc -v` 能运行。
- `cjpm -h` 能运行。
- 你已经有一个空的 `taskbook` 目录。

## 练习

在 `taskbook` 目录里创建一个空的 `main.cj` 文件。下一课会把它改成可运行程序。
